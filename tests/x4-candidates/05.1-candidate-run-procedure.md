# Phase 05.1 Candidate Run Procedure

This procedure separates the verified local process boundary from the later
Phase 05.1 human-only X4 gate. Phase 05.2 does not launch X4, open a save,
mutate game state, or make an admission decision. The committed ledger remains
`runtime-pending`.

## Local package preflight

Generate fresh developer roots outside the repository and outside the game
installation:

<!-- markdownlint-disable MD013 -->

```powershell
pwsh -NoProfile -File tools/x4-verification/build-candidate-extension.ps1 -BuildRoot $BuildRoot -MatrixPath tests/x4-candidates/phase-05.1-candidates.v1.json
```

<!-- markdownlint-enable MD013 -->

For each generated root, verify that `manifest/build-manifest.v1.json` reports
`execution-ready-local-process`, `terminable-external-isolation`, and
`local_readiness_verified = true`. Independently rerun the package contract:

<!-- markdownlint-disable MD013 -->

```powershell
pwsh -NoProfile -File tools/x4-verification/tests/candidate_build_contract.ps1 -Case all
```

<!-- markdownlint-enable MD013 -->

The generated Lua entrypoint is inert metadata. It has no dispatcher, native
call, save access, mutation path, or public control.

## Human-triggered local dispatcher

Run each package explicitly. The command never launches X4:

<!-- markdownlint-disable MD013 -->

```powershell
pwsh -NoProfile -File $GroupRoot/tools/x4-verification/run-candidate-package.ps1 -GroupRoot $GroupRoot -OutputPath $PrivateJsonlPath
```

<!-- markdownlint-enable MD013 -->

The dispatcher schedules the committed group subset in stable candidate-ID
order. Every adapter crosses the fixed external worker deadline and process
tree boundary. A valid local fixture result is classified only as
`authenticated-local-contract`, never `observed-in-X4`.

When the separately owner-provisioned `candidate-producer` delegation and CNG
key are absent, the expected result is
`PRODUCER_ATTESTATION_UNCONFIGURED`. The JSONL proves local process readiness
but is not retainable production evidence.

## Preparation

1. Confirm the exact game version and installed mod identities required
   by the candidate matrix.
2. Select the matching Plan 04 build group. The lifecycle candidate uses
   its exclusive build; the other six candidates use the shared
   read-only build.
3. Create a fresh disposable Creative Custom campaign for this attempt.
   Never use an existing campaign or any save belonging to normal play.
4. Assign a logical run ID. Do not put a user name, machine-local path,
   secret, or raw runtime value in the ID.

## Later human-only X4 execution

The owner launches X4, creates the disposable campaign, runs one bounded
candidate at a time, and observes the three runner stages: execution,
contract, and effect. Stop immediately at any candidate stop condition,
unexpected write signal, schema failure, identity mismatch, or
incomplete record. A stopped run is evidence and must not be relabeled
as passing.

The local fixture provider is replaced only by the separately reviewed X4
adapter boundary for this later gate. Blocking or native-class work must still
cross the external worker; generated Lua must never call `ffi.C` directly.
Neither dispatcher nor runner decides admission. The human operator does not
edit the stream, the build manifest, or the production extension to make a
result pass.

## Safe collection and retention

1. Close the bounded attempt before collection.
2. Only after producer attestation succeeds, pass the exact JSONL stream and
   matching build manifest to the retention boundary:

   <!-- markdownlint-disable MD013 -->

   ```powershell
   pwsh -NoProfile -File tools/x4-verification/retain-evidence.ps1 -EvidencePath $PrivateJsonlPath -BuildManifestPath $BuildManifestPath -DestinationRoot $RetentionRoot
   ```

   <!-- markdownlint-enable MD013 -->

3. Retain under this stable machine-local locator template on Windows:

   ```text
   %LOCALAPPDATA%\LiveGalaxy\runtime-evidence\phase-05.1-plan-05\<logical-run-id>\locator.v1.json
   ```

   The helper owns atomic placement, owner-only permissions, digest
   reread, and locator verification.
4. Immediately run the helper's locator verification mode. If the
   artifact, locator, permissions, or digest cannot be verified,
   classify the run as ephemeral and blocking.
5. Copy only the sanitized logical IDs, schema versions, verdicts,
   dispositions, and digests into a completed handback ledger. Never
   copy raw evidence, private paths, game state, or secrets into Git.

## Handback and admission

Preserve separate execution, contract, and effect verdicts for every
candidate. A valid but unexpected effect is not a pass. Keep the
candidate non-admissible when any verdict fails, retention is
incomplete, a source-action defect exists, identity is incomplete, or
the expected and actual effect IDs differ.

Independent admission consumes the completed sanitized ledger together
with this committed pending ledger and the candidate matrix. The runner
and retention helper cannot promote a candidate. Production seams and
the public package remain unchanged until a later phase separately
admits evidence and authorizes implementation.
