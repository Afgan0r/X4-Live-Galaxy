# Phase 05.4 Plan 01: Owned Native Carrier Summary

Live Galaxy now owns a narrow Lua 5.1 native module that copies caller bytes synchronously into a one-slot local transport and keeps every overlapped buffer, operation record, and module lease alive until Windows reports terminal completion.

## What Was Built

- Added the `x4-carrier-native` `cdylib`/`rlib` with the sole PE initializer `luaopen_live_galaxy_carrier` and no game-state mutation operation.
- Registered the versioned Lua API through the initializer instead of exporting operation symbols.
- Added exact generation tokens, checked fixed-width configuration, one complete-message data slot, one control-result slot, typed capacity/stale/unavailable outcomes, and non-consuming short-output rejection.
- Added a message-mode named-pipe server with `PIPE_REJECT_REMOTE_CLIENTS`, an explicit DACL for the current logon SID, and an actual negative `AccessCheck` using an anonymous impersonation token.
- Added one bounded completion worker. It never calls Lua or X4 APIs and owns only copied bytes, Win32 handles, overlapped records, and fixed-capacity channels.
- Added cancellation/finalization behavior in which Lua requests close and returns immediately. The worker treats `CancelIoEx` as a request, retains storage while completion is pending, and releases it only after terminal completion.

## ABI and Result Contract

| Lua member | Success result | Bounded or terminal result | Rejection boundary |
| --- | --- | --- | --- |
| `abi_version` | Current integer ABI version | N/A | Loader failure is separate |
| `open` | `0`, opaque `generation:slot` token | Transport unavailable | Wrong version, record size, limits, or exhausted generation |
| `connection` | `1` when the matching pipe generation is connected | `0` otherwise | Stale or absent state is not connected |
| `try_send` | `1` for local owned handoff | `2` when the one data slot is occupied or closing | Oversize, stale, or unavailable transport |
| `poll` | `1`, exact complete control bytes | `0` when no complete control is ready | Short output capacity does not consume; stale/closed remain distinct |
| `reset` | Requests cancellation and clears logical capacity | Returns without waiting or draining | Invalid/stale token |
| `close` | Requests cancellation and closes logical handle | Returns without waiting, spinning, or retrying | Invalid/stale token; double close is safe |

`LocalHandoff` means only that the native carrier owns the copied bytes. It does not mean `Received`, `Committed`, durable, or published.

## Safety and Lifetime Contract

- Lua state, callbacks, and borrowed Lua buffers never escape an ABI call.
- The completion worker has fixed one-message data and control capacities; there is no generic pool or unbounded queue.
- The worker retains each `OVERLAPPED`, event, and backing buffer across immediate completion, `ERROR_IO_PENDING`, incomplete polls, cancellation request, and cancellation completion.
- Finalization only flips the cancellation request. It performs no wait, spin, drain, retry, Lua call, or X4 call.
- A native module reference is acquired before the worker starts and is released by `FreeLibraryAndExitThread` only after terminal cleanup.
- Each worker holds generation-local state. Completion from an old generation has no reference to replacement-generation state.
- The pipe is created only after the explicit DACL and remote rejection mode are established. There is no default-security or Carrier A fallback.

## Dependency Features

The exact `windows-sys = 0.61.2` dependency enables only `Foundation`, `Security`, `Storage_FileSystem`, `System_IO`, `System_LibraryLoader`, `System_Performance`, `System_Pipes`, and `System_Threading`. Release panic strategy is `unwind` so every C entrypoint can contain unwinding before it crosses the ABI.

## Decisions Made

The owner approved an explicit deviation from the researched workerless default: exactly one bounded carrier-owned completion worker. The concrete reason was that `CancelIoEx` return is not terminal completion, while Lua finalization cannot wait; without a retained completion owner, arbitrary DLL unload could free live overlapped storage. The approved worker owns no Lua or X4 state and preserves the already accepted one-slot data and control capacities.
