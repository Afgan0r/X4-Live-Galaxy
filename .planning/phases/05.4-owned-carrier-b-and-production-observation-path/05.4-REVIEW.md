## Independent Re-review Findings

### RR-CR-01: Native admission time is mislabeled as X4 capture evidence

**Classification:** BLOCKER (P1)

**File:** `extensions/live_galaxy/lua/live_galaxy_scheduler.lua:28-30`; `extensions/live_galaxy/lua/live_galaxy_observation.lua:34-35`; `crates/x4-carrier-native/src/lua_input.rs:48`; `crates/x4-carrier-native/src/abi_windows.rs:154`

**Trigger:** The real MD callback supplies the string `telemetry_tick`, so the
scheduler fills both capture bounds from `progress_status.monotonic_millis`.
That value is the DLL's Windows monotonic clock, but observation construction
labels it `game_time_millis` and native validation requires that label.

**Rule/evidence:** D-12 requires Lua to supply source-supported capture
metadata, while Plan 03 explicitly says native monotonic metadata controls
real-time admission and cannot be relabeled as source or scheduler truth. The
new Lua test at `carrier_b_contract.lua:119` codifies the wrong substitution.

**Consequence:** Persisted sender evidence makes a false provenance claim and
does not describe a capture window around the X4 getter.

**Minimal fix:** Obtain capture bounds from an actual X4-supported callback or
getter seam and preserve its honest clock label. Keep DLL monotonic time only
for admission/retry scheduling; do not use it as X4 capture evidence.

### RR-CR-02: Reconnect and peer reset do not perform a bootstrap-first protocol fence

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/transport_worker_io.rs:46-63,66-85,88-117`; `crates/x4-carrier-native/src/producer.rs:86-90`; `crates/x4-carrier-native/src/producer_feedback.rs:54-58`; `crates/x4-bridge/src/production_runtime.rs:73-80`; `crates/x4-bridge/tests/actual_rejection_matrix.rs:58-70`

**Trigger:** After peer failure the worker reconnects the pipe and replays a
retained application write. A replacement bridge requires its first frame to
decode as bootstrap, so it rejects that start/batch/completion frame. If the
old write completed before failure, there is no retained write and the
producer hides its handed-off pending bytes, so the replacement receives
nothing. A peer Reset creates a new bootstrap on the existing bridge session,
which is already past its bootstrap state, and retained old controls can also
cross the reconnect fence.

**Rule/evidence:** ADR-LG-013 and Plans 02/03 require compatibility and
reconciliation before fresh collection after reconnect. The added actual test
manually calls `bootstrap("after-restart")`; it never drives Producer through
the failure. The raw transport recovery test proves byte replay, not protocol
recovery.

**Consequence:** A compatible bridge crash/restart during or after a handed-off
message cannot resume without a game-side generation restart, and stale
controls may be applied across the new connection.

**Minimal fix:** Treat reconnect as a protocol fence: clear old application and
control frames, surface the event to Producer, rotate the required identity,
queue a fresh bootstrap first, complete compatibility/reconciliation, and only
then permit fresh collection. Add one real Producer + NativeTransport + bridge
child test that kills the bridge with a handed-off message.

## Critical Issues

### CR-01: The real MD event can never supply the context required by the scheduler

**Disposition:** Fixed in `7958518` and `dba3589`; the actual callback records
X4 game-time bounds around exactly one fact getter.

**Classification:** BLOCKER (P1)

**File:** `extensions/live_galaxy/md/live_galaxy_observation.xml:18`; `extensions/live_galaxy/lua/live_galaxy_runtime.lua:20`; `extensions/live_galaxy/lua/live_galaxy_scheduler.lua:13`; `extensions/live_galaxy/lua/live_galaxy_observation.lua:27-28,60-61`

**Trigger:** The MD cue raises the Lua event with the literal string
`telemetry_tick`, while the registered callback accepts one argument and passes
it as a table containing decimal `capture_start_millis` and
`capture_end_millis` fields.

**Rule/evidence:** D-12 permits a thin X4 callback/getter adapter, and Phase 05.4
requires one real `GetCurRealTime` observation. The actual MD payload is not the
synthetic table injected by `carrier_b_contract.lua` and
`carrier_b_local.lua`.

**Consequence:** Every real tick returns `clock_unavailable` before reserving or
capturing a fact, so the phase's core X4-to-SQLite observation cannot occur.

**Fix:** Define and test the exact X4 `RegisterEvent` callback signature. Supply
bounded capture evidence from the actual callback/game clock seam (or collect it
through the allowed getter seam), and drive the registered callback with the
same event arguments in a contract test.

### CR-02: A burst of compatibility controls is silently discarded

**Disposition:** Fixed in `74b8bd7`; completed controls remain queued until Lua
consumes them, and the actual burst test proves ordered delivery.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/transport_worker.rs:101-115`; `crates/x4-bridge/src/production_runtime.rs:59-78`; `crates/x4-bridge/tests/production_startup/actual_pipe.rs:88-97`

**Trigger:** The bridge sends handshake, collection intent, and demand back to
back. The worker continuously reads them into a capacity-one channel, ignores a
`TrySendError::Full`, drops the completed read, and immediately begins another.
The test drains each control between sends and therefore removes the production
race.

**Rule/evidence:** D-12's typed state machine requires the exact ordered
compatibility/intent/demand sequence; bounded capacity may backpressure but may
not lose admitted control state.

**Consequence:** Intent or demand can disappear, leaving the producer permanently
stuck before `Ready` even though both peers report a compatible session.

**Fix:** Retain a completed control message until Lua consumes the channel slot,
or stop issuing reads while the slot is occupied. Add an actual-pipe test that
sends all three controls before any Lua-side poll and proves ordered delivery.

### CR-03: A compatible bridge restart cannot reconnect to the native server

**Disposition:** Fixed in `2078aa3` and `ef895d5`; replacement recovery is
bootstrap-first, generation-fenced, and restores exact immutable pending bytes.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/transport_worker.rs:41-69,81-115`; `crates/x4-carrier-native/src/abi_windows_io.rs:69-83,145-149`

**Trigger:** When the bridge client closes, read/write polling becomes failed.
The worker clears only the individual operation; it never clears `connected`,
calls `DisconnectNamedPipe`, or enters `begin_connect` again. `begin_connect`
is executed only once at worker startup.

**Rule/evidence:** ADR-LG-008 and Phase D-05 explicitly require a compatible
external bridge to restart independently without restarting X4.

**Consequence:** The native pipe remains in a broken connected instance and a
replacement bridge cannot establish a new session. Recovery requires a
game-facing Lua/DLL restart, contrary to the accepted ownership boundary.

**Fix:** Add an explicit connected/disconnected/reconnecting worker state. On
terminal peer I/O, cancel and drain all operations, disconnect the server pipe,
advance/reset the session fence as designed, and issue a fresh overlapped
connect. Prove kill-and-restart with the actual DLL and bridge process.

### CR-04: Message age is measured from connection start and kills valid long-lived sessions

**Disposition:** Fixed in `474fda9`; production no longer treats connection
lifetime as message age, and a valid post-limit session message is covered.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-bridge/src/production_runtime.rs:81-86`; `config/carrier-b-limits.json:8`; `extensions/live_galaxy/md/live_galaxy_observation.xml:16`

**Trigger:** `connected_at` is captured once, and every later message is rejected
after five seconds of total connection lifetime. The game callback interval is
30 seconds.

**Rule/evidence:** The finite age limit belongs to an in-flight candidate/message,
not the lifetime of a healthy transport session. Availability and reconnect are
separate limits.

**Consequence:** Unless a sample happens within the first five seconds, the first
real observation is rejected. Every healthy session is forcibly terminated no
later than its next post-five-second message.

**Fix:** Remove transport-session age from `serve`. Let the receiver lifecycle
enforce candidate age from its own admitted start time, and implement the
separate inactivity deadline against the last transport progress if required.
Add a >5-second connected-session test with a later valid message.

### CR-05: Retry age starts at zero for production messages

**Disposition:** Fixed in `5e515a2`; the production bootstrap and successor
stages record their first actual native handoff timestamp.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/lua_operations.rs:96`; `crates/x4-carrier-native/src/producer_feedback.rs:129`; `crates/x4-carrier-native/src/producer.rs:72,99-107`

**Trigger:** Production constructs the bootstrap with `now_millis = 0`, and each
successor batch/completion pending item is also constructed at zero.
`mark_local_handoff` retains the minimum of zero and the real monotonic clock.
Any `capacity_unavailable` received after host uptime exceeds 5 seconds is
therefore treated as older than the retry budget.

**Rule/evidence:** D-04 permits the exact retained retry up to two attempts and
five seconds when non-consumption is proven. Existing tests use a synthetic
clock starting at zero and miss the production epoch mismatch.

**Consequence:** Bootstrap, batch, and completion lose their permitted retry in
normal process uptime and pause immediately after the first capacity response.

**Fix:** Initialize each `Pending.first_attempt_at` from the transport monotonic
clock at actual creation/handoff; pass `now` while advancing messages. Add a test
whose first clock value is well above 5,000 ms and exercises all three message
stages.

### CR-06: The mandatory pending-I/O unload proof does not create or assert pending I/O

**Disposition:** Fixed in `df0a806`; the unload test proves live operation
ownership, immutable pending identity, terminal cancellation, unload, and fence.

**Classification:** BLOCKER (P1)

**File:** `extensions/live_galaxy/tests/carrier_b_local.lua:49-56`; `tests/carrier-b-local.ps1:93-117,175-203`

**Trigger:** The harness kills the bridge before calling `carrier:progress(1)`,
ignores that call's result, then writes `actual_native=true` and `sampled=true`
unconditionally. The host checks eventual module unload and token fencing, but
never observes a pending OS operation, owner count, retained pending message, or
terminal completion before storage release.

**Rule/evidence:** Plan 04 makes a real pending operation at `lua_close` a
mandatory lifetime gate. A broken pipe commonly makes the post-kill operation
fail synchronously, which is not the required scenario.

**Consequence:** The suite can report
`PENDING_IO_TERMINAL_AND_MODULE_UNLOADED` without testing the use-after-unload
boundary it claims to qualify.

**Fix:** Establish and inspect a genuinely pending connect/read/write before
closing the Lua state, assert nonzero operation ownership and exact pending
producer identity, then prove cancellation terminality, zero owners, unload,
and stale-token rejection. Do not derive pass fields from constants.

### CR-07: Operational history is unbounded and can exhaust durable storage

**Disposition:** Fixed in `474fda9`; diagnostics rotate at a fixed byte bound,
aggregate repeated events, and retain suppression and gap counters.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-bridge/src/diagnostics.rs:43-78`; `crates/x4-bridge/src/production_runtime.rs:27,51,55,76,80,85,89,98,100`

**Trigger:** Every wait/reject/disposition transition is appended and flushed to
one JSONL file with no byte/count/age bound, rotation, retention, aggregation,
or repeated-event rate limit.

**Rule/evidence:** LOG-04 and ADR-LG-006 require diagnostic streams to have
independent finite resource bounds.

**Consequence:** Normal long-running operation or a reconnect/rejection loop can
grow the file until disk exhaustion, compromising the adjacent SQLite store and
recovery path.

**Fix:** Add an explicit bounded retention/rotation policy plus bounded repeated
event aggregation and lost/suppressed counters. Test the exact boundary and
retained-history behavior.

### CR-08: Both reset paths leave a session that cannot bootstrap again

**Disposition:** Fixed in `2078aa3`; peer Reset requests an actual reconnect and
the Producer preserves identity through replacement bootstrap.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/lua_operations.rs:114-117`; `crates/x4-carrier-native/src/lua_transport.rs:22-43`; `crates/x4-carrier-native/src/producer_feedback.rs:55-60`; `extensions/live_galaxy/lua/live_galaxy_carrier.lua:61`

**Trigger:** Lua `reset` requests transport shutdown, resets only registry queue
fields, and clears the producer while leaving the wrapper open. Subsequent calls
return transport/producer unavailable. A received typed `Reset` likewise clears
the current pending bootstrap and enters `AwaitingCompatibility` without
creating a replacement bootstrap message.

**Rule/evidence:** Reset/reconnect is an explicit ABI-2 operation and D-05
requires bounded recovery with fresh generation fencing.

**Consequence:** Neither local nor peer-requested reset can reach a new handshake;
the only recovery is an undocumented full wrapper/state recreation.

**Fix:** Make reset atomically construct a fresh generation, transport, producer,
and bootstrap, or define it as terminal close and require `carrier.new()`.
Whichever contract is selected, test the complete reset-to-compatible sequence
and stale-token rejection.

### CR-09: A stalled peer bypasses candidate age and inactivity limits

**Disposition:** Fixed in `474fda9`; timed peer reads drive candidate expiry and
the independent inactivity deadline releases retained capacity.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-bridge/src/production_runtime.rs:81-100`; `crates/x4-carrier-native/src/transport_peer.rs:30-40`; `crates/x4-carrier-native/src/abi_windows_peer.rs:57-76`; `crates/observation-ingest/src/candidate_limits.rs:126-140`

**Trigger:** Bridge `receive` is a blocking `ReadFile`. After a `SectionStart`, a
peer can remain connected and send nothing; `serve` never regains control to
check a timer, and production never calls `expire_candidates`.
`max_message_inactivity_millis` is parsed but not used by the runtime.

**Rule/evidence:** D-06 and ADR-LG-006 require finite candidate age, inactivity,
retained capacity, and work under every failure path.

**Consequence:** One stalled local peer retains the candidate and aggregate slot
indefinitely and prevents recovery or fresh collection.

**Fix:** Use bounded overlapped/nonblocking peer reads or a timed wait loop,
expire the active candidate during idle periods, close/reset the session at the
inactivity boundary, and test a start-then-stall case with exact capacity
release.

### CR-10: A failed native write drops handed-off bytes without feedback

**Disposition:** Fixed in `2078aa3`; uncertain write bytes remain immutable and
are reconciled only after replacement bootstrap compatibility.

**Classification:** BLOCKER (P1)

**File:** `crates/x4-carrier-native/src/transport_worker.rs:119-128`; `crates/x4-carrier-native/src/lua_producer_operations.rs:92-102`

**Trigger:** Lua marks the message locally handed off when it enters the worker
channel. If `begin_write` then fails, the worker drops the owned `Vec<u8>` and
only clears `data_busy`; it sends no failure to the producer and does not requeue
the immutable bytes.

**Rule/evidence:** Local handoff is explicitly not receiver `received`; exact
bytes must remain retryable until an unambiguous disposition.

**Consequence:** The producer retains a handed-off pending message that
`pending_bytes()` will no longer expose, so no retry or terminal transition is
possible. Collection deadlocks with the only transport copy lost.

**Fix:** Retain/requeue the exact buffer until write completion or surface a
typed terminal/non-consumption result back to the producer that makes the same
bytes retryable under the finite retry budget. Add synchronous and asynchronous
write-failure tests.
