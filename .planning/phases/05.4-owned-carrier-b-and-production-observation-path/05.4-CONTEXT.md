# Phase 05.4: Owned Carrier B and Production Observation Path

**Created:** 2026-09-04
**Status:** Phase split and carrier direction approved; dedicated discussion, research and planning pending.
**Authority:** The Phase 05.3 accepted context, ADR-LG-001 through ADR-LG-024, the 2026-09-04 Docs MCP publication, and the owner's explicit decision to proceed with Carrier B in a separate phase.

## Locked decisions from the split

- Phase 05.3 remains source-agnostic and owns generic Rust contracts, validation and durable publication.
- This phase owns the minimal Live Galaxy-controlled production carrier and the X4-to-Rust observation path behind the Phase 05.3 carrier-neutral facade.
- Carrier B is a minimal Rust/C native library with a Lua-facing boundary. It is not a general plugin platform and does not own observation policy, publication policy or strategic behavior.
- The transport exposes no fleet, economy, diplomacy, institution or other game-state mutation command.
- Complete-message, connection, capacity, send, receive, control-poll, duplicate, permanent rejection and ambiguous outcomes remain distinct and bounded.
- Retry preserves the exact immutable batch identity and bytes. A local native write is not a volatile `received` acknowledgement or durable `committed` receipt.
- Carrier A (`sn_mod_support_apis`) is retained as research evidence and may not be presented as a safe fallback unless new executable evidence closes its bounded nonblocking and typed-result gaps.
- Automatic save pause/resume is unsupported under current evidence. A numeric cooldown must not be invented from the historical implementation.
- Heavy faction-ship conformance belongs to Phase 05.5 and the conditional station remainder to Phase 05.6.

## Evidence that triggered Carrier B

The registered Docs MCP publication combined the base X4 and support-API snapshots with:

- `carrier-a-message-mode-source-20260903-v2`;
- `save-boundary-source-20260903-v1`;
- `x4-probe-md-pulse-a70af158-v1`.

It established the following planning constraints:

1. Carrier A is conditionally message-oriented only when the server is `PIPE_TYPE_MESSAGE` and `PIPE_NOWAIT` is installed successfully. Its wrapper does not expose the `SetNamedPipeHandleState` result, collapses zero and hard failures, and does not length-check positive counts. The required bounded nonblocking behavior and retry classification therefore cannot be proven.
2. The selected instantiated 50 ms MD cue is a best-effort game-time pump. It is not a hard deadline or real-time service guarantee. Load and UI reload recreate Lua and invalidate old pipe state.
3. First-party save completion and availability shapes exist, but no proven save-begin or durability boundary supports automatic resume.

## Required discussion before planning

The dedicated phase discussion must still resolve the exact native ABI and ownership boundary, supported platforms and packaging, process and handle lifecycle, buffer ownership, message and queue bounds, reconnect/reset handshake, failure reporting, compatibility policy, and the smallest disposable X4 proof. The phase split does not pre-approve implementation or broaden filesystem, installation or runtime mutation authority.

## Required gates

- Research, plan-check, code review and verification.
- Security review for native input, control authority, memory ownership and persistence boundaries.
- Rust and X4/Lua test contracts, including static, pure-Lua, fake-adapter and disposable runtime evidence.
- X4 probe and SETA evidence for delivery, lifecycle, reconnect and measured callback work.
- Mutation testing where deterministic validation or safety invariants can be weakened without ordinary tests failing.
- Nyquist validation only if planning exposes a requirement-to-test coverage gap.

AI specification/eval and UI design gates are not selected because this phase changes neither model-visible behavior nor a custom interface.

## Deferred ideas

Multiple in-flight batches, dynamic credit, durable partial staging, generalized native extension infrastructure, mutation commands, report delivery, heavy observation coverage and full unattended soak remain outside this phase unless the owner admits them through their owning later phase.
