#### ABI input validation and synchronous copy

**Analog:** `crates/observation-ingest/src/wire.rs` (tracked; strict boundary)
and `extensions/live_galaxy/lua/live_galaxy_component_discovery.lua:11-23,52-85`
(tracked; Lua-side checked FFI boundary).

Use the existing strict-boundary order as the safe-side model: reject before
construction/allocation, preserve typed rejection, and never retain raw input.
The native helper must validate null/length combinations, checked conversions,
negotiated maximums, handle generation, and slot capacity before dereferencing;
copy accepted bytes synchronously into DLL-owned memory. No LuaJIT/X4 pointer or
callback may survive the ABI call.

The Lua FFI analog declares the external boundary locally and keeps X4 getter
ownership in Lua:

```lua

    local C = ffi.C

        count_stations = function(_, faction_id)
            return C.GetNumAllFactionStations(faction_id)
        end,
        new_buffer = function(_, count)
            return ffi.new("UniverseID[?]", count)
        end,
        fill_stations = function(_, buffer, count, faction_id)
            return C.GetAllFactionStations(buffer, count, faction_id)

```

For Carrier B, keep X4 getter calls in the existing LuaJIT FFI seam, but load the
owned carrier through the source-backed normal chain: a UI-registered Lua
wrapper calls `package.loadlib(exact_extension_relative_path,
exact_luaopen_symbol)`, invokes the returned initializer, and retains the
resulting module API for that Lua generation. Do not use `ffi.load` or assume
process-wide `ffi.C` registration for the carrier. Use explicit `pcall` around
the wrapper/native calls and preserve distinct open, symbol, initializer, and
typed-operation failures; never turn a thrown native failure into an empty
successful observation.

**No analog:** pointer validation, `catch_unwind`, `#[unsafe(no_mangle)]`, and
DLL teardown are new native responsibilities. The planner must keep these in
the dedicated crate and test null/zero, oversize, integer overflow, injected
panic, stale/double-close handle, and cancellation. `catch_unwind` does not
catch `panic=abort`; verify the release panic profile.

#### Pump-first scheduling, reservation, and exact retry

**Analogs:** `crates/observation-ingest/src/scheduler.rs:76-167`,
`crates/observation-ingest/src/feedback/slot.rs:49-175`, and
`crates/observation-ingest/src/feedback/slot_transition.rs:3-31` (tracked).

The scheduler already encodes the required sequence:

```rust
pub fn deliver_pulse(&mut self, pulse: DeliveredPulse) -> SchedulerOutcome {
    self.budget.refill(self.clock.now_millis());
    let reserve = self
        .transport
        .terminal_reserve
        .get()
        .min(pulse.available_bytes);
    let bulk_capacity = pulse
        .available_bytes
        .saturating_sub(reserve)
        .min(self.transport.max_pump_bytes.get());
    if let Some(pumped_bytes) = self.pump_pending(bulk_capacity) {
        return self.outcome(pumped_bytes, reserve, None);
    }
    let admission = self.select_admission(bulk_capacity);
    self.outcome(0, reserve, admission)
}
```

The stop-and-wait slot is the sole raw-byte owner and distinguishes exact
replay, capacity, and ambiguity:

```rust
pub fn stage_batch(&mut self, batch: ImmutableApplicationBatch) -> SlotAdmission {
    if let Some(pending) = &self.pending {
        return classify(&pending.batch, pending.disposition, &batch, true);
    }
    match self.released.as_ref()
        .map(|held| classify(&held.batch, Some(held.disposition), &batch, false)) {
        None | Some(SlotAdmission::Staged) => {}
        Some(replay) => return replay,
    }
    self.pending = Some(PendingBatch { batch, disposition: None });
    self.released = None;
    self.stage = DeliveryStage::CollectionProgress;
    SlotAdmission::Staged
}
```

Carrier B/Lua orchestration must copy this behavior, not the historical FIFO:

1. Poll control/progress first.
2. Retry only the exact immutable pending bytes, with a finite budget scoped to
   the current epoch.
3. Reserve native/transport capacity before invoking X4 getters.
4. Collect at most one bounded continuation and retain it on backpressure.
5. After retry exhaustion, abandon that transfer, pause collection, rate-gate
   availability checks, and start fresh collection only after compatible
   reconnect and receipt reconciliation.

Never repeat getters for a transport retry, create multiple in-flight batches,
or let the five-second availability target renew send attempts.

#### Durable lifecycle and publication boundary

The application lifecycle validates before slot admission and keeps all policy
outside the carrier:

```rust
pub fn submit(&mut self, input: LifecycleInput) -> Result<LifecycleResult, LifecycleError> {
    if self.retained.is_some() {
        return Err(LifecycleError::BlockedAmbiguous);
    }
    let message = decode_complete_message(
        &input.bytes,
        self.limits.complete_message_bytes.get(),
    ).map_err(|_| LifecycleError::DecodeRejected)?;
    validate_context(&message, &input.context, input.epoch)?;
    let batch = ImmutableApplicationBatch::new(
        input.epoch,
        input.identity,
        input.bytes,
        input.context.replay_identity(input.work),
    ).ok_or(LifecycleError::DecodeRejected)?;
    match self.slot.stage_batch(batch) {
        SlotAdmission::Staged => {}
        SlotAdmission::ExactReplay(disposition) => {
            return Ok(LifecycleResult::Disposition(disposition));
        }
        SlotAdmission::IdentityConflict => {
            return Ok(LifecycleResult::Disposition(
                ReceiverDisposition::PermanentlyRejected,
            ));
        }
        SlotAdmission::CapacityUnavailable => {
            return Ok(LifecycleResult::Disposition(
                ReceiverDisposition::CapacityUnavailable,
            ));
        }
        SlotAdmission::AlreadyStaged => return Err(LifecycleError::SlotInvariant),
    }
    self.slot.mark_local_handoff().map_err(|_| LifecycleError::SlotInvariant)?;
    self.dispatch(message, input.context, input.work, input.now)
}
```

Publication must call `ObservationRepository::publish` and finalize decision
authority only after committed-new/committed-replay or committed reconciliation.
Ambiguous attempts retain typed request/authority while raw bytes stay in the
slot. The bridge must not stop at parsing or a local handoff; the production
acceptance boundary is an independent SQLite read of the committed revision
and receipt.

## Shared Patterns

### Typed boundary and fail-closed ordering

**Sources:** `crates/x4-bridge/src/facade.rs:12-43`,
`crates/x4-bridge/src/ingress.rs:50-82`,
`crates/observation-ingest/src/wire.rs` (tracked), and
`crates/observation-application/src/lifecycle.rs:39-76`.

Apply to native ABI, bridge adapter, Lua carrier, and lifecycle wiring:

1. Check compatibility/session and current generation/epoch.
2. Check kind/context, pointer/length or raw-byte size, and typed values.
3. Check capacity and mutable conditions before allocation or state mutation.
4. Return a bounded typed reason; preserve prior accepted/pending state.
5. Never report `Received` or `Committed` for a local handoff.

### Exact identity, epoch, and retry ownership

**Sources:** `crates/x4-bridge/src/session.rs:68-114`,
`crates/observation-ingest/src/feedback/slot_transition.rs:3-31`, and
`crates/observation-application/src/lifecycle_publication.rs:15-67`.

Use typed producer/batch/section/revision/epoch identities. Retry the same
immutable bytes only while the current state proves it safe. A stale epoch,
uncertain commit, load, or UI reload establishes a source boundary: discard
incomplete work, reconcile exact durable receipts, and require a fresh baseline.
No availability probe renews a send budget.

### Bounded resources and real-time semantics

**Sources:** `crates/observation-ingest/src/scheduler.rs:127-167`,
`scheduler_budget.rs`/`scheduler_queue.rs` (tracked), and
`extensions/live_galaxy/tests/scheduler_contract.lua:11-40`.

Keep independent finite bounds for callback work, message bytes, native slot,
control/result visibility, retries, bridge staging, logs, and availability
checks. Inject clocks into pure policy tests; never sleep or call wall-clock
time there. Treat the five-second availability target as conditional on
continuing callbacks, not a hard X4 deadline. Ordinary and SETA measurements
must record callback cost, gaps, occupancy, and detection interval.

### Logging and diagnostics

**Sources:** `crates/x4-bridge/src/listener.rs:113-185`,
`extensions/live_galaxy/lua/live_galaxy_runtime.lua:45-71,317-345`, and
the tracked logging skill reference.

Use stable event names and bounded fields: component, clock meaning, attempt /
epoch identity, operation, outcome, reason, duration, bytes, and retry count.
Aggregate pulse/frame repetition; do not log raw payloads, private paths,
secrets, prompts, hidden reasoning, pointers, or unrestricted native errors.
Player console status is concise; structured developer history is detailed and
separate. If a required journal sink cannot initialize, bridge startup fails
honestly; later sink degradation remains visible without falsely acknowledging
durability.

### Rust file-size and module ownership

**Source:** `crates/observation-persistence/src/sqlite.rs:1-169` plus the
Phase 05.3 Plan 04 summary (tracked planning artifact).

Every Rust production and test source file remains at or below 200 physical
lines. Split only by cohesive responsibility: exports/composition, ABI safety,
handle lifecycle, transport, state transitions, and test fixtures. Do not
weaken the safe workspace lint or create numbered dumping-ground modules.

### Real boundary tests

**Sources:** `crates/x4-bridge/tests/named_pipe_contract.rs:15-179`,
`crates/observation-ingest/tests/scheduler_policy.rs:55-177`,
`crates/observation-application/tests/lifecycle_contract.rs:19-177`,
`crates/observation-persistence/tests/crash_recovery.rs:25-95`, and
`extensions/live_galaxy/tests/module_loading_spec.lua:135-273` (tracked).

Copy scenarios, not historical constants:

- accepted, malformed, oversize, stale generation/epoch, incompatible hello;
- capacity-unavailable without state consumption;
- exact replay with unchanged bytes and no duplicate publication;
- ambiguous commit, proven-not-committed retry, and still-ambiguous blocking;
- panic/exception, cancellation, stale/double-close, and invalid pointer/length;
- both startup orders, absent/slow bridge, disconnect at each boundary, and
  control-capacity behavior;
- real Lua module loading through extension-relative paths and strict fakes;
- independent SQLite read/restart proving committed revision and receipt;
- loader, load/UI reload, repeated reload, clean exit, ordinary time, and SETA
  disposable X4 evidence.

Local Rust, pure-Lua, fake-adapter, package, and SQLite tests are necessary but
cannot claim X4 loader/lifetime, game scheduling, SETA, or real getter-backed
observation behavior. The final production claim requires the user-operated
