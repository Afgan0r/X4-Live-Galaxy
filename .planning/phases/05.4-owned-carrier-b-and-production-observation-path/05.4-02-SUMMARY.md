## Deviations from Plan

### Owner-Approved Scope Additions

1. Direct exhaustive/compile consumers were updated in `legacy_candidate.rs`, `completion_contract/coverage.rs`, persistence `context.rs`/`record.rs`/`schema.rs`, `section_state.rs`, and `hydration_validation.rs`. These were required to keep the sole D-13 migration compiling and preserve `PointMeasurement` as a distinct value.
2. `sender_evidence.rs`, `carrier_control_types.rs`, `production_runtime_message.rs`, and the production-startup test modules are mechanical responsibility splits required by the 200-line repository limit; behavior and dependencies did not change.
3. The plan omitted the identity-bootstrap seam. `BridgePeer` can only receive producer data and send controls, while bound control decoding needs the DLL-owned tuple. The approved fix accepts one strict handshake-only bootstrap on the producer-to-bridge direction before any application data, then sends bound compatibility controls. Application payloads, extra fields, wrong versions, and oversize bootstrap frames reject.
4. `complete_message_digest` was added to observation-ingest beside the shared wire/control contract so both sides use the locked SHA-256 implementation without adding a bridge dependency.
5. `ProductionObservationSession::invalidate_source_scope` narrowly forwards the existing lifecycle fence and clears retained volatile receive context after disconnect/rejection.

### Auto-Fixed Issues

1. The first runtime-limit mapping placed work and candidate count into CandidateLimits age/inactivity parameters. The actual-pipe GREEN test exposed permanent batch rejection; the schema was corrected to the real constructor axes before commit.
2. The migrated point-measurement enum required explicit persistence names and completion coverage matching. It remains a separate semantic value and was not collapsed into another coverage class.
3. Typed disposition validation initially collapsed several receiver outcomes. The codec now preserves every `ReceiverDisposition` name required by the control contract.

### Process Deviations

- `section_state.rs` and `hydration_validation.rs` were initially edited before their direct-consumer scope was reported; the owner subsequently approved both. This late-report deviation is recorded explicitly.
- An initial diff-only line-count audit missed an untracked new Rust file. The file was split, and every later gate used `source-size-lint` over all tracked and untracked Rust sources.
