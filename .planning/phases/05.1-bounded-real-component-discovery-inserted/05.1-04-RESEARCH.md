# Phase 05.1 follow-up research: faction station bound

## Question

How should the first complete faction-station observation handle an observed
station count above the original pre-work bound of 16?

## Evidence

- **Observed in X4, build 9.0.0.0:** The corrected native faction token reaches
  station enumeration and returns `enumeration_overflow` before allocation,
  conversion, metadata, capacity, observation, or completion marker. The
  configured Argon scope exceeds 16.
- **Observed call shape:** The installed local X4 MCP extension calls
  `GetNumAllFactionStations(faction.id)`, allocates an `UniverseID` buffer only
  after its count, then calls `GetAllFactionStations` with the same faction
  value. Its discovery loop performs one faction per slice.
- **Observed scheduling precedent:** The same extension limits its heavier
  trade-off station work to ten station scans per slice and documents UI stalls
  when faction-wide enumeration repeats. This is a performance warning, not a
  permission to copy its implementation or remove Live Galaxy's hard bound.

## Transport correction

Live Galaxy's own Lua runtime and Rust bridge cap one pipe frame at 2 KiB. A
single 64-station observation is therefore not an evidence-backed transport
shape. The existing Rust pending snapshot already admits up to 128 frames
atomically, so the safe successor is one bounded station observation per frame
followed by one completion marker for the same scope and version.

## Decision

Replace the obsolete single-frame aggregate with at most 64 deterministic,
per-station frames and one completion marker. Keep the pre-allocation overflow
check and all-or-nothing Rust admission. The operation reads only owner, sector,
and people capacity once per candidate; it adds no pagination, retry, new
schema, or gameplay mutation.

## Risk Boundary

Native X4 runtime cost at the 64-station limit remains pending the disposable
smoke test. A count above 64 must stay `enumeration_overflow`; it may not be
silently truncated or widened without a future measured plan.
