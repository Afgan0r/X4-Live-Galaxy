## Summary

The predecessor has already established the failure that motivates this phase: the selected-sector probe produced `sector_capacity=call_error`, while its metadata and owner predicates were `ok`. [VERIFIED: tests/x4-disposable/01-probe-evidence.md] This is evidence that the selected-sector operation is the wrong capacity target, not evidence that component-local capacity is globally unavailable. [VERIFIED: tests/x4-disposable/01-probe-evidence.md]

The smallest evidence-backed successor is an original Lua adapter that enumerates a single **pre-bounded component class and owner scope**, canonicalizes only the bounded returned identifiers, sorts them, then performs metadata, ownership, and capacity calls for a fixed per-cycle prefix. [MEDIUM: installed `x4_live_mcp` call-shape precedent] The installed reference uses `C.GetNumAllFactionStations(faction_id)` followed by `C.GetAllFactionStations(stations, count, faction_id)` and converts returned IDs to Lua components before component reads. [MEDIUM: F:/SteamLibrary/steamapps/common/X4 Foundations/extensions/x4_live_mcp/ui/x4_live_mcp.lua:2383-2390] It also uses `C.GetPeopleCapacity(component64, "", false)` only with a component-local numeric identifier. [MEDIUM: F:/SteamLibrary/steamapps/common/X4 Foundations/extensions/x4_live_mcp/ui/x4_live_mcp.lua:1453-1462]

**Primary recommendation:** Implement a station-only, owner-scoped `component_discovery` adapter behind the existing Lua telemetry seam: reject an over-limit raw enumeration before conversion or per-component reads, emit only sorted real `asset:station:<id>` records with their real sector, owner, and component-local capacity, and otherwise emit an explicit health/discovery failure with no observation or completion marker.

### Pattern 1: Pre-bound before expensive work

**What:** Read the raw enumeration count, reject any value that is absent, non-integral, negative, or above a named hard maximum, and do not allocate, convert identities, query metadata, or call capacity APIs in that outcome. [MEDIUM: installed X4 Live station-enumeration precedent; VERIFIED: 05.1-CONTEXT.md]

**When to use:** Every raw component class enumeration, including the first station-only tracer.

**Required semantics:** `overflow` and `enumeration_unavailable` are non-observation outcomes. They must not emit a completion marker, because the scope did not complete. [VERIFIED: crates/observation-ingest/src/batch.rs:156-188]

### Pattern 2: Deterministic bounded component slice

**What:** Convert and validate the returned identifiers only after the raw bound passes; sort by an opaque canonical numeric-string identity; choose the first `MAX_COMPONENTS_PER_CYCLE` entries; then read a fixed, ordered field set for each. [ASSUMED]

**When to use:** The initial hypothesis tracer must use one component class and one owner scope. The exact hard limits are planning choices, not measured X4 limits. [ASSUMED]

**Required fact shape:** The asset ID must identify the component class and stable component identity, for example `asset:station:<stable-id>`; the sector relationship comes from a component-to-sector lookup, not from promoting the sector into an asset. [ASSUMED]

### Pattern 3: All-or-nothing accepted scope

**What:** Build the prospective scope entirely in Lua; serialize it only when every selected component has valid required identity, sector relationship, owner, and capacity facts. Rust then applies it atomically and only reconciles membership after a successful completion marker. [VERIFIED: crates/observation-ingest/src/batch.rs:32-85; crates/observation-ingest/src/batch.rs:156-188]

**When to use:** A complete bounded station slice. A component-level source failure must leave the prior accepted scope intact.

### Anti-Patterns to Avoid

- **Sector as synthetic asset:** The current adapter constructs `asset:` from a sector identity; Phase 05.1 must replace that only with a component-derived asset ID. [VERIFIED: extensions/live_galaxy/lua/live_galaxy_x4_discovery.lua]
- **Count-as-completion:** A raw count at or below the limit is not a complete scope until the bounded fill, conversion, required reads, serialization, Rust admission, and completion marker all succeed. [VERIFIED: crates/observation-ingest/src/batch.rs:156-188]
- **Truncating after discovery work:** Do not enumerate an oversized collection and silently take a prefix. The overflow check belongs before allocation, conversion, or component-native calls. [VERIFIED: 05.1-CONTEXT.md]
- **Suppressing failure as empty:** `known_empty` requires successful completion of the same runtime scope; a source failure is `partial`, `unknown`, or `unsupported` as appropriate. [VERIFIED: .planning/STATE.md]
- **Using reference code as implementation:** The reference has unresolved redistribution/provenance status; only observed call shapes may guide original code. [VERIFIED: 05.1-CONTEXT.md]

## Failure and Bounds Semantics

| Stage | Required failure result | Component reads allowed? | Observation / marker allowed? |
| --- | --- | --- | --- |
| API/table unavailable or count invalid | `enumeration_unavailable` | No | No |
| Raw count exceeds hard limit | `enumeration_overflow` | No | No |
| Fill count is invalid, exceeds requested count, or differs from validated count | `enumeration_partial` | No | No |
| Conversion / duplicate identity / sort-key failure | `identity_invalid` or `enumeration_partial` | Only already-validated prior items | No |
| Component metadata, owner, sector, or capacity call/type/value failure | `facts_unsupported` with a bounded class-only diagnostic | At most the configured per-cycle prefix | No |
| All selected records valid but per-cycle prefix is not the complete declared scope | `partial` | At most prefix | No complete marker; preserve prior complete scope |
| Full declared bounded slice valid and admitted | `fresh` / `available` | Fixed prefix only | Observation plus matching completion marker |

The state labels above are required planning semantics except where marked as implementation-specific names; existing evidence already proves that rejected Rust batches preserve the prior projection and that an incomplete scope does not reconcile membership. [VERIFIED: crates/observation-ingest/src/batch.rs:84-115; crates/observation-ingest/src/batch.rs:156-188]

## Common Pitfalls

### Pitfall 1: Allocating from an untrusted native count

**What goes wrong:** A native count drives `ffi.new` or iteration before it is bounded, creating a game-thread cost/memory hazard. [ASSUMED]

**How to avoid:** Validate count type, integral range, and a small hard maximum before buffer allocation or any per-component operation. The limit must be a named constant tested at `limit` and `limit + 1`. [ASSUMED]

### Pitfall 2: Completing an intentionally sliced scope

**What goes wrong:** A prefix marker removes previously accepted members outside the prefix during reconciliation. [VERIFIED: crates/observation-ingest/src/batch.rs:156-188]

**How to avoid:** Do not emit a marker unless the declared scope itself is fully enumerated and all members are present. A multi-cycle cursor needs a distinct partial-scope contract before it can be admitted; it is out of scope for the initial tracer. [ASSUMED]

### Pitfall 3: Treating an owner string as an authoritative faction identity

**What goes wrong:** Component metadata may be missing, malformed, or have different representation than the faction scope. [MEDIUM: installed X4 Live precedent]

**How to avoid:** Validate owner as an opaque bounded ID, retain the enumeration scope separately in diagnostics, and reject the component record if the required ownership relationship cannot be represented. [ASSUMED]

### Pitfall 4: Reusing the old transport evidence as discovery evidence

**What goes wrong:** The final Phase 1 smoke observed reconnect, not component facts. [VERIFIED: tests/x4-disposable/01-probe-evidence.md]

**How to avoid:** Report local tests, fake tests, and a fresh Phase 05.1 disposable probe independently; do not claim compatibility or component availability before the new run. [VERIFIED: 05.1-CONTEXT.md]

## Open Questions (RESOLVED)

These decisions resolve the implementation forks. They do not upgrade any native
claim to observed X4 evidence.

1. **Native station enumeration and component-local capacity availability**
   - **Accepted implementation decision:** Bind the exact researched station count/fill,
     identity conversion, component metadata, and capacity seam behind a probe-gated
     adapter. Local contract and static-binding success is implementation-resolved only.
   - **Evidence gate:** Native availability is `pending-X4` until the written human
     disposable Creative Custom probe observes it. If it fails, retain
     `facts_unsupported` and require a separately authorized revision; do not widen the
     scope or choose another seam automatically.

2. **Raw count maximum and runtime cost**
   - **Accepted implementation decision:** Use one named hard count maximum as a
     deterministic safety and rejection bound. A raw count over it is rejected before
     allocation, conversion, or component reads; a count within it processes the entire
     owner-scoped result.
   - **Evidence gate:** The maximum is not a measured cost claim. Runtime cost and SETA
     evidence remain `pending-X4` and belong to Phase 7 after the bounded probe records
     its local observations.

3. **Owner normalization**
   - **Accepted implementation decision:** Require a valid bounded opaque owner value
     that matches the predeclared owner scope. A mismatch or malformed value is
     unsupported and cannot form an observation or completion marker.
   - **Evidence gate:** Authoritative native owner semantics remain `pending-X4` until
     the disposable probe observes the selected binding in X4.
