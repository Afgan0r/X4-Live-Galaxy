# X4 Reference Research: Faction-Station Enumeration Bound

## Scope

This research evaluates the existing X4 native station enumeration call shape,
the accepted faction-ID representation, and a safe bound for one complete
Live Galaxy snapshot. It does not modify X4, installed extensions, saves, or
runtime state.

## Evidence classification

| Classification | Evidence | Conclusion |
| --- | --- | --- |
| Observed in installed X4 | X4 build `9.0.0.0` reached `GetNumAllFactionStations` and returned an overflow at the Live Galaxy bound of 16 before buffer allocation. | The native count is available at runtime and the current Argon scope is larger than 16. |
| Observed in installed X4 Live MCP | `x4_live_mcp.lua` calls `C.GetNumAllFactionStations(faction_id)`, allocates `UniverseID[?]` with that count, then calls `C.GetAllFactionStations(stations, count, faction_id)`. | The count-then-fill sequence is the smallest local precedent for complete faction enumeration. |
| Observed in installed X4 Live MCP | The same code converts each returned station with `ConvertStringToLuaID(tostring(stations[index]))`, then uses `ConvertIDTo64Bit` for component-local calls. | The returned buffer is a `UniverseID` sequence; Lua-side component IDs are reconstructed before component calls. |
| Observed in installed X4 Live MCP | Capacity is queried as `C.GetPeopleCapacity(component64, "", false)` on a component-local 64-bit ID. | A station component, not a sector, is the supported target shape evidenced locally. |
| Observed in installed X4 Live MCP | Faction-wide discovery is performed one faction per slice; heavier station work is limited to ten scans per slice. | Repeated faction-wide scans have a documented local performance cost; this is a warning, not copied policy. |
| Inferred | A pre-allocation hard bound preserves memory and game-thread limits while allowing one all-or-nothing result. | Raise the obsolete bound only to a measured, explicit value; do not truncate. |
| Unknown | No installed vanilla documentation or API header was found that specifies a universal maximum, ordering guarantee, cost at 64, or behavior above the requested buffer count. | `64` is a Live Galaxy safety budget, not a vanilla compatibility guarantee. |

## Faction-ID representation

The observed call sites pass the Lua `faction_id` directly to both native
functions. No conversion to a 64-bit component ID is performed for the
faction argument. The returned station values are separately converted from
the native `UniverseID` representation into Lua component IDs, and then into
64-bit IDs for component-local metadata and capacity calls.

This establishes the following narrow contract for Live Galaxy:

1. Pass the configured Lua faction identifier unchanged to
   `GetNumAllFactionStations` and `GetAllFactionStations`.
2. Treat the count as native output and validate it before allocation.
3. Convert each returned `UniverseID` to a Lua component ID before metadata
   access; do not use the faction ID or sector ID as a station substitute.

## Bound and slicing recommendation

The minimum safe plan is a single deterministic faction slice with a hard
pre-allocation maximum of `64` stations:

1. Read the native count.
2. Return `enumeration_overflow` immediately when count is greater than 64.
3. Allocate exactly the reported count only after that check.
4. Fill the buffer with the same faction identifier.
5. Validate the returned count and every candidate before producing any
   observation.
6. Produce one complete observation or no observation; never emit a prefix.

This plan is justified as a bounded increase over the observed 16-station
failure and is sufficient for the current measured Argon test scope. It does
not justify a cursor, silent truncation, retries, dynamic widening, or a claim
that every faction will fit. A count above 64 must remain an explicit
fail-closed result until a new measured plan is approved.

## Risks and unknowns

- Native enumeration order is not documented by the inspected sources. Live
  Galaxy must sort by its own validated stable key before serialization if
  deterministic ordering is required.
- The installed reference filters known stations before its later work, while
  Live Galaxy's acceptance contract requires complete owner-scoped facts. The
  reference therefore proves call shape, not the complete-observation policy.
- The runtime cost of 64 count/fill entries plus per-station metadata and
  capacity calls remains pending disposable X4 smoke evidence.
- Faction identity semantics outside the tested Argon scope are unknown.
- A zero count is not evidence that the faction has no authoritative stations
  unless the native API contract for that context is established; preserve the
  existing missing/unsupported distinctions.

## Research boundary

The `F:\Agent Projects\X4` checkout was treated as dirty and without a usable
origin, so its source was not used as fresh repository evidence. The installed
`x4_live_mcp` extension was read-only observed call-shape evidence. No live
state, save, game installation, or installed extension was changed.

## Recommendation

Implement the 64-station pre-allocation guard and all-or-nothing snapshot
described above, then run the planned disposable X4 smoke test with bounded
trace and exact build/mod inventory. Keep `enumeration_overflow` as the only
safe result above the bound and classify runtime cost and complete fact
availability as pending until that test succeeds.
