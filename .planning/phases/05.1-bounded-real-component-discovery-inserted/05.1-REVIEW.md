# Phase 05.1: Code Review Report

**Reviewed:** 2026-08-29T00:00:00Z
**Depth:** deep
**Files Reviewed:** 9
**Status:** issues_found

## Summary

The Rust admission and health-only/no-marker flow preserve the prior projection
for rejected envelopes. However, the production native-station adapter does not
match the locally observed X4 Live FFI boundary, and the passing guard and Lua
contracts do not exercise that boundary. No native X4 claim is justified; the
required disposable Creative Custom probe remains pending.

## Critical Issues

### CR-01: Native count and fill values are rejected before discovery can start

**File:** `extensions/live_galaxy/lua/live_galaxy_component_discovery.lua:68-76`

**Failure:** The adapter passes both native returns directly to `valid_integer`,
which accepts only `type(value) == "number"`. The established X4 Live call shape
normalizes both `C.GetNumAllFactionStations` and `C.GetAllFactionStations` with
`tonumber` before using them. A LuaJIT FFI integer result can be cdata, so the
adapter returns `enumeration_unavailable` or `enumeration_incomplete` even for
a valid native enumeration. The fake returns Lua numbers and therefore cannot
detect this production failure.

**Evidence:** The installed read-only precedent at
`F:/SteamLibrary/steamapps/common/X4 Foundations/extensions/x4_live_mcp/ui/x4_live_mcp.lua:2384-2388`
uses `tonumber` for both values. The phase plan explicitly requires finite
integral count/fill normalization.

**Smallest viable fix:** Normalize each protected result before validation,
then reject non-finite/non-integral values:

```lua
local count = tonumber(raw_count)
if count == nil or not valid_integer(count) then return nil, "enumeration_unavailable" end
```

Apply the same conversion to `filled` and add a fake returning a cdata-shaped
numeric value where the locked Lua runtime can represent one.

### CR-02: The station buffer is decoded with the wrong representation and indices

**File:** `extensions/live_galaxy/lua/live_galaxy_component_discovery.lua:25, 79-81`

**Failure:** The native buffer is allocated as `uint64_t[?]`, but the observed
call uses `UniverseID[?]`. More importantly, the adapter reads indices `1..count`
and sends each raw FFI element straight to component APIs. The established
native call site reads `stations[0]` through `stations[count - 1]` and converts
each returned `UniverseID` through `ConvertStringToLuaID(tostring(...))` before
component operations. At runtime this skips the first station, reads one element
past the end, and passes an unconverted opaque identifier to `ConvertIDTo64Bit`,
`GetComponentData`, and `GetPeopleCapacity`; it can produce a false failure or
facts for the wrong station.

**Evidence:** The installed read-only X4 Live precedent at
`F:/SteamLibrary/steamapps/common/X4 Foundations/extensions/x4_live_mcp/ui/x4_live_mcp.lua:2386-2390`
uses `UniverseID[?]`, zero-based indexing, and `ConvertStringToLuaID`. The
current test fake is a one-based Lua table, so it masks all three differences.

**Smallest viable fix:** Allocate the observed `UniverseID[?]` type, iterate
`for index = 0, count - 1`, convert each entry to a Lua component before
identity and component reads, and reject a failed conversion without emitting an
observation. Add a zero-indexed-buffer fixture that fails with the current code.

### CR-03: The package guard never inspects the submitted production package

**File:** `extensions/live_galaxy/tests/component_discovery_package_guard.ps1:47-83`; `extensions/live_galaxy/tests/run_contracts.ps1:10-13`

**Failure:** `component_discovery_guard` invokes only self-contained strings.
It never calls `Test-ComponentDiscoveryPackage` with the changed Phase 05.1
paths and their actual source, nor with the phase diff. Consequently any newly
introduced report, command, effect, persistence, model, UI, or mutation token
in an allowlisted production file still leaves the suite green. This bypasses
the telemetry-only authority gate that the phase treats as mitigation for
T-05.1-04.

**Evidence:** The only invocations at lines 52 and 75 consume `$allowlisted`
and `$expectedFailures`; the runner at line 11 runs only `-SelfTest`.

**Smallest viable fix:** Keep the self-test, then make the runner enumerate the
declared Phase 05.1 production paths (or supplied changed paths), read each
allowlisted file, and fail when `Test-ComponentDiscoveryPackage` rejects it.
Reject any changed production path not in the fixed allowlist.

## Warnings

### WR-01: The focused Lua suite can pass while the real FFI binding is broken

**File:** `extensions/live_galaxy/tests/component_discovery_contract.lua:7-70`; `extensions/live_galaxy/tests/component_discovery_binding_contract.ps1:8-18`

**Failure:** The behavioral fake models only a one-based table and Lua-number
returns. It does not assert that allocation is avoided on overflow, count/fill
normalization is performed, the returned buffer is zero-indexed, or a raw
`UniverseID` is converted before component reads. The PowerShell check only
matches symbol spelling. Thus both checks pass for the demonstrated broken
native binding.

**Evidence:** The focused suite passed in this review while CR-01 and CR-02 are
present. The plan requires bound-before-allocation and explicitly limits static
binding evidence to source presence, not native behavior.

**Smallest viable fix:** Record `new_buffer` calls and assert zero allocations
on overflow; add a zero-indexed buffer fixture; require an injected
`to_component` conversion seam and assert it is called before every metadata or
capacity read. Keep the human X4 probe pending as the only native-runtime proof.
