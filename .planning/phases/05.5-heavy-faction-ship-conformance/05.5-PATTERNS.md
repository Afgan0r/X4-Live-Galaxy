## Pattern Assignments

### Observation-domain evidence and identity

**Assign to:** `section_state.rs`, `observation.rs`, `section.rs`, and any planner-selected ship-detail helper.
**Analogs:** `crates/observation-domain/src/section_state.rs:3-31,39-68,82-112`; `crates/observation-domain/src/observation.rs:25-62,89-108,116-140`; `crates/observation-domain/src/section.rs`.

Keep the existing evidence vocabulary rather than representing unavailable detail as an empty value. The current section model explicitly distinguishes `Fresh`, `KnownEmpty`, `Unknown`, `Partial`, `Stale`, and `Unsupported`, plus independent freshness, coverage, and availability axes:

```rust
pub enum SectionQuality {
    Fresh,
    KnownEmpty,
    Unknown,
    Partial,
    Stale,
    Unsupported,
}
pub enum SectionCoverage {
    Complete,
    KnownEmpty,
    PointMeasurement,
    Unknown,
    Partial,
    Unsupported,
}
pub enum SectionAvailability {
    Available,
    Unavailable,
}
```

`CaptureWindow::new` rejects reversed timestamps (`section_state.rs:39-50`), and `SectionState::with_evidence` reconstructs a completed state without dropping any axis (`section_state.rs:82-96`). Use those constructors for core identity and every detail section. A detail getter failure must leave the core record publishable only when the phase contract marks that detail as non-blocking; required unavailable fields must block completion with an explicit state.

The record constructor rejects empty content (`observation.rs:25-62`). Its replay fingerprint frames source scope, record ID, entity, content, source time, and observation version (`observation.rs:89-108`); extend that identity framing for ship records instead of hashing ad hoc Lua strings. Duplicate handling is explicit (`observation.rs:116-140`: `Idempotent`, `Conflict`, `DifferentIdentity`), so retries of immutable ship bytes must remain idempotent while changed payloads are conflicts.

**Planner guidance:** keep the core ship identity/owner/type/class/location and detail sections as typed domain values. Preserve `not_applicable` separately from zero, empty, absent, stale, inaccessible, unknown, and unsupported. If adding typed cargo/crew/loadout structures would exceed 200 lines, create narrowly named helper modules under `observation-domain`; do not hide the schema in the bridge or Lua adapter.

### Heavy admission, fairness, and bounded work

**Assign to:** `crates/observation-ingest/src/scheduler.rs`, `scheduler_budget.rs`, and focused scheduler tests.
**Analogs:** `scheduler.rs:116-166`; `scheduler_budget.rs:26-88,90-143`; `tests/scheduler_policy.rs:124-175`.

The scheduler stages only bounded inputs, refills from the real-time clock, reserves terminal bytes, and pumps pending work before admitting new work (`scheduler.rs:116-166`). Heavy ship work must use the existing `WorkKind::Heavy` path, not a second queue or an unbounded special case. `SchedulerBudget::can_admit` requires permits, zero overrun debt, in-flight capacity, declared-work bounds, and a heavy permit (`scheduler_budget.rs:54-64`); `admit` consumes the relevant permit (`:66-88`). Completion returns a heavy permit and turns excess work into bounded debt or `CollectorRejected` (`:90-117`). Refill repays debt before issuing new capacity (`:120-143`).

```rust
pub(crate) fn can_admit(&self, intent: &CollectionIntent) -> bool {
    self.permits > 0
        && self.debt.0 == 0
        && self.in_flight.len() < self.limits.burst.get()
        && self.accepts_declared(intent.declared_work())
        && (intent.work_kind() == WorkKind::Light || self.heavy_permits > 0)
}
```

Copy the test shape from `scheduler_policy.rs:124-157`: a fake clock, one heavy permit, explicit completion, and an assertion that completion is idempotent. Retain the overrun-debt test (`:160+`) and add cases for a heavy ship that is blocked while a pending immutable batch drains, never starving ordinary light work. Numeric normal/SETA budgets remain research-owned unknowns; the planner should wire measured limits rather than invent constants.

### Durable production admission and publication

**Assign to:** `production.rs`, `production_admission.rs`, `production_runtime.rs`, and their bridge tests.
**Analogs:** `crates/x4-bridge/src/production.rs:26-29,74-120,123-169,172-198`; `production_admission.rs:39-85,88-117`; `production_runtime.rs:42-99,101-147`; `tests/carrier_b_publication.rs:13-53,55-134`; `tests/carrier_b_recovery.rs:18-109`.

`ProductionObservationSession` owns the lifecycle and retains the last received `(BatchId, bytes, LifecycleContext)` (`production.rs:26-29`). `submit_received` decodes under the message limit, reuses the prior context only for the exact same identity and bytes, creates `LifecycleInput`, submits through source-boundary or normal lifecycle, then records the received tuple (`production.rs:80-120`). Scope invalidation, uncertainty, and expiry clear that retained tuple (`:123-143`); revision selection is durable and refuses exhaustion (`:154-169`).

```rust
let context = if let Some((prior_identity, prior_bytes, prior_context)) = &self.last_received
    && prior_identity == &identity
    && prior_bytes == &bytes
{
    prior_context.clone()
} else {
    self.receiver_context(&bytes)?
};
```

Admission must bind history before submission, pass immutable bytes and the transport epoch to `submit_received`, and send a disposition containing message ID, section key/revision, and digest (`production_admission.rs:53-85`). A failed response is `ResponseLoss`; `finish_error` records `ambiguous` only when the receiver disposition was `Committed`, otherwise `rejected` (`:39-50,111-117`). Do not convert an inaccessible/unknown ship detail into a committed empty field during this mapping.

The runtime waits for a compatible bootstrap, computes the durable revision floor, sends handshake + collection intent + one demand, admits progress, and sends the next demand only after `Committed` (`production_runtime.rs:42-99,121-147`). Preserve the explicit ABI/schema/policy/canonicalization/digest tuple in the handshake (`:127-145`). This is the correct place to add a heavy intent or section key; do not add a second connection protocol.

The publication test opens a real `ProductionObservationSession`, submits start and completion, drops it, then independently reopens SQLite and reads the current revision (`carrier_b_publication.rs:13-53`). Keep malformed/context-mismatched messages non-publishing (`:101-134`). The recovery tests prove exact replay without duplicate publication (`carrier_b_recovery.rs:18-32`), reconcile a response-loss commit to the exact receipt (`:34-81`), and allow retry only after a proven-absent attempt (`:83-109`). Extend those tests with ship records, required detail blockers, and digest/receipt equality.

### Carrier B native producer and recovery

**Assign to:** `producer_collection.rs`, `producer_message.rs`, `lua_input.rs`, `producer_recovery.rs`, and native tests.
**Analogs:** `crates/x4-carrier-native/src/producer_collection.rs:8-27,30-64,66-115`; `producer_message.rs:16-112`; `lua_input.rs:12-130`; `producer_recovery.rs:5-49`.

The native producer enforces `Ready -> SectionReserved -> Collecting`, rejects a second fact or data-limit violation (`producer_collection.rs:8-27`), and validates finish success, capture ordering, quality, availability, coverage, consistency, and stable identity before setting `finished` (`:30-64`). `progress` refuses to overwrite a pending batch, requires bounded nonzero work, assembles immutable messages, and enters `PendingStart` (`:66-100`). Keep this state machine as the sole source of pending bytes.

```rust
if self.pending.is_some() {
    return Ok(ProducerOutcome::CapacityUnavailable);
}
if self.state != ProducerState::Collecting
    || !self.finished
    || work_units == 0
    || work_units > self.limits.max_work
{
    return Err(ProducerError::InvalidTransition);
}
```

`producer_message.rs:16-72` is the canonical envelope assembly pattern: typed IDs, section key/revision, expected record count, content digest, and immutable start/batch/completion messages. Completion binds contract versions and a `PointMeasurement` coverage certificate (`:74-112`). The ship payload should use the same envelope and certificate; only the section schema and expected count change.

`lua_input.rs:12-40` defines exact BEGIN/FACT/FINISH keys; `:42-87` validates the begin evidence and constructs the sender evidence with source epoch/boundary; `:89-130` extracts bounded typed facts and maps finish enums. Add only allowlisted ship fields and preserve unknown/unsupported states instead of silently accepting extra keys.

On a new connection, `observe_connection` ignores zero/stale generations, increments transport epoch, increments revision when an attempt was incomplete, discards incomplete state, queues a bootstrap, and enters `AwaitingCompatibility` (`producer_recovery.rs:5-41`). This is the analog for reconnect churn and SETA restart; do not reuse a stale heavy batch after transport identity changes.

### Lua scheduler, runtime, and Carrier B adapter

**Assign to:** `live_galaxy_scheduler.lua`, `live_galaxy_runtime.lua`, `live_galaxy_carrier.lua`, and any ship observation adapter selected by the planner.
**Analogs:** `live_galaxy_scheduler.lua:8-64`; `live_galaxy_runtime.lua:1-19,21-66,68-101`; `live_galaxy_carrier.lua:3-43,45-67,70-127`; `live_galaxy_component_discovery.lua:98-173`.

The scheduler calls Carrier B progress first, polls control, checks capacity, begins evidence, reserves a section, captures, pushes, finishes evidence, and finishes the section (`live_galaxy_scheduler.lua:27-64`). It uses a re-entry guard and a local `finish` function that clears the guard on every return (`:15-25`). Heavy ship collection must be one bounded step through this path; it must not call getters while the producer reports occupied capacity.

The runtime uses extension-relative `package.path` and requires the carrier, observation, and scheduler modules (`live_galaxy_runtime.lua:1-19`). It allowlists diagnostic details and deduplicates them (`:21-43`), latches the `game_loaded` boundary until a sample succeeds, wraps the scheduler in `pcall`, suppresses re-entry, and clears the boundary only after `sampled` (`:45-66`). Initialization closes Carrier B if observation initialization fails and registers exactly one event callback (`:68-101`). Reuse these lifecycle boundaries for normal and sustained SETA evidence.

The carrier adapter has an exact operation list and ABI check (`live_galaxy_carrier.lua:3-43`), validates protected-call result shapes and bounded status strings (`:45-67`), and owns close/reset finalization (`:70-104`). `carrier.new` validates loader, initializer, API, ABI 2, token shape, and source/limits (`:107-127`). The existing `LIMITS` are small acceptance values (`max_records = 1`, `max_work = 1`); they are not heavy-phase defaults. The planner should route measured heavy limits through the same options path and preserve the exact API check.

`live_galaxy_component_discovery.lua:106-145` is the closest Lua enumeration analog: bound work, `pcall` count/fill calls, reject count/fill mismatch, validate stable IDs, reject duplicates, and sort deterministically. Lines `146-173` validate metadata, capacity, canonical owner, and owner scope. Copy the count/fill/bounds/sort/error structure only. Do not copy station IDs, station capacity names, or owner assumptions into ship semantics. This is a partial analog for the new ship field schema and faction disposition evidence.

## Shared Patterns

### Trust boundary and field validity

**Sources:** `producer_collection.rs:30-64`; `lua_input.rs:42-130`; `production_admission.rs:53-85`; `section_state.rs:3-31`.
**Apply to:** every ship adapter, Carrier B producer, bridge admission, and domain model.

- X4 getters are untrusted inputs. Validate exact key sets, type/size limits, stable identity, capture ordering, source epoch/boundary, and enum agreement before admitting bytes.
- Preserve source strength and availability. Transport, normalization, or publication may not upgrade a weak/unknown source claim.
- Required detail failure blocks completion; non-required detail failure is explicitly classified, never collapsed into zero or empty.

### Pump-first bounded scheduling

**Sources:** `scheduler.rs:116-166`; `scheduler_budget.rs:54-143`; `live_galaxy_scheduler.lua:27-45`.
**Apply to:** heavy and light collectors, normal ticks, and sustained SETA.

Always progress/poll pending Carrier B state before beginning new source work. Enforce declared work, raw bytes, record count, allocation, retries, in-flight, and heavy-permit bounds. Keep wall-clock refill and overrun debt separate from accelerated game time.

### Immutable publication and recovery

**Sources:** `production.rs:80-120,123-143`; `producer_collection.rs:66-100`; `producer_recovery.rs:18-41`; `carrier_b_recovery.rs:18-109`.
**Apply to:** retries, reconnects, response loss, and process restart.

Retry the exact retained bytes with the same identity/digest. Invalidate retained context on source uncertainty or expiry. A response-loss commit is ambiguous until reconciled; retry only after proving the attempt was not committed. Transport epoch and durable revision prevent stale heavy batches from being republished.

### Safe diagnostics and artifact evidence

**Sources:** `live_galaxy_runtime.lua:21-43`; `run_contracts.ps1:1-73`; `tools/package-live-galaxy.ps1`; `05.4-carrier-b-evidence.md`.
**Apply to:** Lua diagnostics, bridge history, package output, and disposable reports.

Use allowlisted diagnostic classes and deduplicate transitions. Do not log raw prompts, private payloads, or unbounded getter values. Separate automated contract evidence, package identity/digest evidence, local harness measurements, and in-game ordinary/SETA evidence; each report must state what it does not prove.
