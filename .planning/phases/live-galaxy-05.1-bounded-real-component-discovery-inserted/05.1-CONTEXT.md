# Phase 05.1: Bounded Real Component Discovery - Context

**Gathered:** 2026-08-29
**Status:** Ready for planning
**Mode:** Reconstructed from approved successor routing and current X4 evidence

<domain>
## Phase Boundary

Investigate and implement the separately authorized bounded enumeration of real
X4 components needed to replace the unsupported selected-sector capacity call.
Carry real component-derived asset, capacity, and ownership facts through the
existing telemetry-only Lua-to-Rust path while preserving explicit partial,
unknown, and unsupported results.

This phase is the conditional D-09 / OBS-06 evidence successor created after the
Phase 1 capability vector isolated `sector_capacity=call_error`. It is not the
general Lua and X4 verification foundation; that remains Phase 05.2.

</domain>

<decisions>
## Implementation Decisions

### Locked scope

- Use installed vanilla X4 as the first source for API availability and event
  semantics. The X4 Live repository and installed extension are observed call
  shape precedents only.
- Implement original Live Galaxy logic. Do not copy third-party code while its
  license and redistribution status remain unresolved.
- Enumerate only a deterministic bounded slice. The planner must specify the
  pre-work limit, per-cycle budget, ordering, and explicit overflow result.
- Real components must remain real assets. Do not promote a sector into a
  synthetic asset or use the failed sector-as-capacity-target operation.
- Missing, malformed, unavailable, partial, and unsupported results remain
  distinct. Never fabricate `known_empty` or fall back to fixed identities.
- Preserve the existing telemetry framing, protocol negotiation, bridge
  reconnect behavior, strict Rust admission, and atomic no-partial-update
  semantics.
- Retain telemetry-only behavior. No report, acknowledgement, command, effect,
  persistence, model, public UI, or game-state mutation vocabulary is admitted.
- Never inspect or modify saves. Any game evidence uses a disposable Creative
  Custom campaign under a written, bounded probe procedure.

### Verification boundary

- Static/package checks, pure Lua tests, fake-adapter contracts, Rust tests, and
  disposable in-game evidence remain separately classified.
- A fake proves only the adapter contract. Only a fresh disposable X4 9.00 run
  can establish actual component enumeration, native-call behavior, runtime
  cost, and compatibility.
- Correlated diagnostics are opt-in, attempt-scoped, bounded, sanitized, and
  disabled by default. They retain no raw payloads, native error text, runtime
  identifiers, saves, or unbounded logs.

### Agent discretion

- Select the smallest current X4 read-only enumeration seam supported by fresh
  evidence.
- Choose cohesive Lua and Rust module boundaries that satisfy existing project
  size and responsibility gates.
- Choose focused fixture shapes and deterministic ordering keys, provided they
  do not invent X4 authority or widen the runtime scan.

</decisions>

## Evidence Classification

- **Observed:** the selected-sector capacity call returned `call_error`; bridge
  transport and reconnect worked in the recorded disposable attempts.
- **Documented locally:** Plan 01-11 forbids component enumeration and routes it
  to a separately authorized bounded successor.
- **Inferred:** a component-local target is the smallest credible successor seam
  because the installed reference uses capacity calls on components.
- **Unknown:** the exact safe enumeration API, complete fact-class availability,
  per-frame cost, and compatibility until fresh Phase 05.1 evidence exists.

Skill learning: none — this context applies existing X4 integration and testing
rules for bounded probes, explicit unsupported results, correlated diagnostics,
and separate in-game evidence. It does not establish a new reusable rule.
