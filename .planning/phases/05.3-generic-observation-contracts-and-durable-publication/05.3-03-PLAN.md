<interfaces>
Consume the exact Plan 02 `ValidatedSectionRevision`, `DecisionRevisionSet`, typed identity/digest/version values, frozen dependencies, and expected-current-pointer contract from `05.3-02-SUMMARY.md`. Persistence must not decode a looser alternate candidate format.

Existing analogs to copy by behavior, not schema:
- `CheckpointPort::compare_and_set` / `reread_ack` for explicit CAS and acknowledgement.
- `FakeCheckpointPort` preflight ordering: validate, exact replay, collision, predecessor check, then accept.
- Strict size-first/versioned checkpoint decode and integrity binding in `checkpoint.rs`.
- Explicit crash-point/recovery outcomes in `mind-persistence::recovery`.

New exact repository surface:
- `ObservationRepository::publish(&mut self, request: PublishRequest) -> PublishOutcome`.
- `PublishRequest` contains one `ValidatedSectionRevision`, exact expected current pointer, and exact frozen dependencies.
- `PublishOutcome` distinguishes `CommittedNew`, `CommittedReplay`, `Conflict`, `StalePointer`, `StaleDependency`, `PermanentRejection`, and `Ambiguous`.
- `ObservationRepository::pin_decision(&mut self, set: &DecisionRevisionSet) -> Result<DecisionPinReceipt, RepositoryError>` validates every referenced revision and creates one durable `DecisionRevisionPin` plus ordered links.
- `ObservationRepository::load_decision_pin(&self, decision: &DecisionSnapshotId) -> Result<DecisionRevisionPin, RepositoryError>` returns the exact durable revision set.
- `ObservationRepository::unpin_decision(&mut self, receipt: &DecisionPinReceipt) -> Result<UnpinOutcome, RepositoryError>` uses the exact pin receipt/CAS identity; it removes pin reachability only and never directly deletes revision content.
- `PublicationReceipt`, `CurrentRevision`, `DecisionRevisionPin`, `DecisionPinReceipt`, `UnpinOutcome`, `RetentionPolicy`, and bounded `RepositoryDiagnostic` values.
</interfaces>

| Validated volatile revision -> repository port | Caller attempts to authorize durable current observation state. |
