# Phase 05.3: Code Review Report

## Narrative Findings (AI reviewer)

### P1-01 (BLOCKER): The fallible hydration API still lets ordinary consumers mint validated authority

**Locations:** `crates/observation-ingest/src/validated_revision.rs:31-70`, `crates/observation-ingest/src/hydration_validation.rs:12-75`, `crates/observation-ingest/src/lib.rs:72-74`

**Observable failure:** `DurableRevisionParts`, all of its fields, and `ValidatedSectionRevision::try_from_durable_parts` remain public and re-exported. The replacement validator checks record ordering, candidate-local entity consistency, coverage, versions, and the content digest, but it cannot authenticate the producer completion certificate and does not validate `manifest_digest` at all. A workspace consumer can therefore assemble public domain values, compute the content digest, choose arbitrary source/session/context/manifest metadata, receive a `ValidatedSectionRevision`, and pass it to the public publication authority path. The compile-fail example proves only that the removed *old method name* no longer compiles; it does not prove that consumers cannot construct validated authority. Iteration-2 P1-04 is not closed.

**Fix:** Seal the raw-parts constructor to the persistence/ingest seam, or introduce a crate-private hydration token obtainable only after repository integrity validation. If a public fallible constructor is intentionally required, extend its input to carry and revalidate every completion invariant, including a recomputable manifest/certificate binding, and add a downstream compile-fail test that attempts the current `try_from_durable_parts` path.

### P1-02 (BLOCKER): Restart accepts caller-forged freshness and can leave partial authority after failure

**Locations:** `crates/observation-application/src/lifecycle_restore.rs:19-48`, `crates/observation-persistence/src/hydration.rs:23-26`, `crates/observation-persistence/src/types.rs:55-69`, `crates/observation-ingest/src/eligibility/restore.rs:9-48`

**Observable failure:** `restore_current_snapshot` is public and accepts arbitrary public-field `CurrentRevision` values. `CurrentRevision::hydrate` validates only the revision; it never binds the receipt's section, revision, content digest, predecessor, or `accepted_at` to that revision. The restore then trusts `current.receipt.accepted_at`, so a caller can pair a valid old revision with a freshly constructed receipt and make stale evidence eligible again. The operation also installs all pointers before hydration, then mutates current/session/version state item by item; if a later item fails, it returns `false` with a partially restored lifecycle that cannot be safely retried because the index is no longer empty. Iteration-2 P1-02 therefore remains incomplete even though SQLite now persists acceptance time.

**Fix:** Make lifecycle restoration load the canonical snapshot from its owned repository, validate each revision/receipt pair as a unit, and construct all hydrated revisions plus merged fences in temporary state. Swap the complete index/stager state only after every entry validates. Add tests for a mismatched receipt, failure in the second item, no mutation after failure, and retry after rejection.

### P1-03 (BLOCKER): Multi-section restore can regress the accepted entity-version fence

**Locations:** `crates/observation-application/src/lifecycle_restore.rs:34-48`, `crates/observation-ingest/src/accepted_versions.rs:11-18`, `crates/observation-persistence/src/sqlite_current.rs:6-23`

**Observable failure:** Current revisions are restored in section-key order, and each successful item calls `record_committed_revision`, which unconditionally overwrites the global `(source scope, entity) -> (version, digest)` entry. If two current sections contain the same entity and the lexicographically later section carries an older version, restart lowers the accepted fence. An equal version with different content is likewise silently replaced. Subsequent staging can then admit a regression or conflicting equal-version observation that the live pre-restart path rejects. The new same-batch/cross-batch tests cover candidate-local staging but not reconstruction of the global committed fence.

**Fix:** Aggregate every hydrated current revision into one provisional accepted-version map before mutating the stager. Reject lower/equal-conflicting entries or merge only according to an explicitly defined monotonic rule, then install the map atomically. Test two current sections containing the same entity with reverse section-key/version order and an equal-version digest conflict.

### P1-04 (BLOCKER): Durable decision pins are not integrity-checked on open or load

**Locations:** `crates/observation-persistence/src/sqlite.rs:22-44`, `crates/observation-persistence/src/sqlite.rs:96-118`, `crates/observation-persistence/src/sqlite_pins.rs:66-114`, `crates/observation-persistence/src/record.rs:61-71`, `crates/observation-persistence/src/schema.rs:53-62`

**Observable failure:** Repository open validates foreign keys plus revision/receipt integrity, but never scans decision pins. Pin loading checks contiguous positions and parses keys/revisions, then returns the caller-supplied decision ID without recomputing `record::decision_identity` from the loaded set. A damaged database can delete all links for a parent pin (which violates no foreign key), or replace a link with another existing revision, and still open successfully. `load_decision_pin` then returns a different or empty revision set under the original immutable decision identity, breaking exact durable decision-snapshot authority and retention reachability.

**Fix:** Validate every decision pin during repository open/recovery and on load: require a non-empty canonical link set, reject duplicate-key replacement, reconstruct a `DecisionRevisionSet`, recompute its decision identity, and require equality with the stored ID. Add corruption fixtures for a missing link, zero links, and a link replaced by another valid revision.

### P2-01 (WARNING): Publication replay discards the repository's authoritative receipt timestamp

**Locations:** `crates/observation-application/src/lifecycle_publication.rs:103-135`, `crates/observation-persistence/src/fake.rs:33-50`, `crates/observation-persistence/src/sqlite_write.rs:128-148`

**Observable failure:** Both repositories deliberately tolerate a replay request carrying a different `accepted_at` and return the original durable receipt. The application collapses `CommittedNew` and `CommittedReplay`, discards that receipt, and finalizes with the volatile attempt timestamp. A correctly pre-restored current revision happens to return `AlreadyFinalized`, but any valid integration path that reconstructs publication authority without that already-finalized entry can refresh durable evidence despite the repository returning the original time. This makes the post-durable finalization contract depend on bootstrap call ordering.

**Fix:** Pass the returned `PublicationReceipt` into finalization and use `receipt.accepted_at` for committed-new, committed-replay, and committed reconciliation evidence. Add a replay test with a later request timestamp and an otherwise empty/reconstructed index; assert eligibility uses the original durable age.
