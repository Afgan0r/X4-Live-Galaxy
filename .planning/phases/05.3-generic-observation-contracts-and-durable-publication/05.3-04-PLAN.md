<interfaces>
Existing surfaces to compose and narrowly correct:
- `decode_complete_message(&[u8], usize) -> Result<CompleteMessage, EnvelopeDecodeError>` checks size before strict decoding.
- `GenerationStager::{start_section_with_context, stage_section_batch, completion_certificate, complete_section}` owns keyed volatile candidates and yields only `ValidatedSectionRevision` after exact completion/current checks.
- `PublishRequest::from_accepted(AcceptedPublication)` owns the exact validated revision and revocable session authority.
- `ObservationRepository::publish` and `SqliteObservationRepository::reconcile_publication` remain the durable outcome authorities.

Exact lower-level seams added by this plan:
- `SlotTurnover::{Released, RetainedExactRetry, BlockedAmbiguous}` reports whether the next application identity may enter.
- `AmbiguityResolution::{Committed, ProvenNotCommitted, StillAmbiguous}` is accepted only while the slot is in `AmbiguousPublication`.
- `StopAndWaitSlot::{confirm_turnover, apply_reconciliation, mark_retry_handoff}` preserve one pending or released-replay byte owner and never create a queue/window.
- `DecisionRevisionIndex::prepare_publication(ValidatedSectionRevision) -> Option<AcceptedPublication>` creates or reuses revocable authority without changing decision-current state.
- `DecisionRevisionIndex::finalize_committed(&AcceptedPublication, u64) -> FinalizationOutcome` revalidates exact authority, source session, pointer, and frozen dependencies before one idempotent in-memory installation.
- `PublishRequest::{attempt_identity, retained_bytes}` expose deterministic typed identity and checked logical ownership cost without raw diagnostics.

Application surface:
- `ObservationLifecycle<R>` owns one slot, one `GenerationStager`, one `DecisionRevisionIndex`, one repository, and at most one `RetainedPublicationAttempt`.
- `LifecycleInput` binds transport epoch, outer application `BatchId`, owned raw bytes, injected work/time, and `LifecycleContext::{Start(CandidateContext), Batch, Completion(CompletionCurrent)}`; decoded/context mismatch is terminal before staging.
- `LifecycleLimits::new(max_complete_message_bytes, max_retained_attempt_bytes, max_ambiguous_age_millis, max_reconcile_attempts)` accepts only non-zero injected values and has no production `Default`.
- `PublicationReconciler` delegates to the existing SQLite classifier and never implements a second reconciliation algorithm.
- `ObservationLifecycle::{submit, reconcile_ambiguous, retry_proven_not_committed}` is the only composition API.
- `RetainedPublicationAttempt` owns the exact `PublishRequest`, `PublishAttemptIdentity`, prepared authority, accepted/start times, checked logical-byte charge, reconcile count, and `AttemptState::{Ambiguous, RetryEligible}`; raw bytes remain owned once by the blocked slot.

<gap_root_cause>
Plans 01-03 implemented strict decoding, feedback, keyed completion, eligibility, and durable persistence as separate contract islands. The slot has no explicit release/turnover consumer, and `DecisionRevisionIndex::accept` changes eligibility before durable publication. The verifier therefore found no complete strict-bytes → slot → keyed candidate → publication → decision-current path.
</gap_root_cause>

<scope_exception>
The eighteen-file surface is necessary and atomic because the verification gap is one disconnected end-to-end key link spanning existing ingress/feedback, assembly/authority, persistence, workspace registration, and the new application tracer. Splitting that link into another plan would create intermediate artifacts that cannot independently prove the gap and would increase coordination without changing product scope. The tasks remain ordered inside this plan: stabilize slot ownership first, stabilize publication authority second, then compose and verify the complete path. Reuse the existing ports/state machines and add only the exact turnover, prepare/finalize, request-retention, and application-composition seams required by the failed truths.
</scope_exception>
