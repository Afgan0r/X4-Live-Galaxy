#### Typed identity and immutable value objects

**Source:** `crates/observation-domain/src/identity.rs:1-65`.

```rust

    pub fn new(value: impl Into<String>) -> Option<Self> {
        let value = value.into();
        (!value.trim().is_empty()).then_some(Self(value))
    }
```

Reuse newtype construction, `NonZeroU64`, checked accessors, and derived canonical ordering. Add separate typed source, producer-incarnation, transport epoch, section, batch, record, and decision identities; do not overload `EntityId`, generation, or a global sequence.

#### Independent freshness, quality, coverage, and completion

**Source:** `crates/observation-domain/src/section.rs:5-89`.

```rust
pub enum SectionQuality { Fresh, KnownEmpty, Unknown, Partial, Stale, Unsupported }
pub enum SectionFreshness { Fresh, Stale }
pub enum SectionCoverage { Complete, KnownEmpty, Unknown, Partial, Unsupported }

pub struct SectionState {
    freshness: SectionFreshness,
    coverage: SectionCoverage,
}

pub fn quality_for_empty_section(
    scope: &EntityId,
    marker: Option<&CompleteMarker>,
) -> SectionState {
    match marker {
        Some(marker) if marker.scope() == scope => {
            SectionState::new(SectionFreshness::Fresh, SectionCoverage::KnownEmpty)
        }
        Some(_) => SectionState::new(SectionFreshness::Fresh, SectionCoverage::Partial),
        None => SectionState::new(SectionFreshness::Fresh, SectionCoverage::Unknown),
    }
}
```

Keep these axes independent. A content-bound completion certificate may preserve source coverage but must never promote `partial`, `unknown`, or `unsupported` to `complete`; zero-record `known_empty` requires a matching completion marker.

#### Record duplicate/replay classification

**Source:** `crates/observation-domain/src/observation.rs:10-102`.

```rust
pub enum DuplicateDecision { Idempotent, Conflict, DifferentIdentity }

pub fn classify_duplicate(
    accepted: &ObservationRecord,
    candidate: &ObservationRecord,
) -> DuplicateDecision {
    if accepted.entity_id != candidate.entity_id {
        return DuplicateDecision::DifferentIdentity;
    }
    if accepted.version == candidate.version && accepted.content == candidate.content {
        DuplicateDecision::Idempotent
    } else {
        DuplicateDecision::Conflict
    }
}
```

Reuse the exact identity-plus-bytes distinction, but replace the existing `u64` FNV-like `replay_fingerprint` with versioned SHA-256 digests for batch manifest/content identity (the research explicitly approves `sha2`). A same identity with changed bytes is terminal conflict.

#### Behavioral tests to copy and extend

**Sources:** `crates/observation-ingest/tests/batch_reconciliation.rs:47-198`, `batch_bounds.rs:42-130`, `crates/observation-domain/tests/reconciliation_policy.rs:24-98`, `identity_section_contract.rs:32-82`.

Copy the table of behaviors, not the old numeric constants:

- staged frames do not alter accepted state until a valid terminal completion;
- invalid marker, mixed version, equal-version changed membership, stale marker, malformed, oversized, and out-of-order input preserve the prior accepted projection;
- exact complete replay is idempotent;
- interleaved keyed sections are isolated and aggregate counters release on drop;
- zero-record matching completion is `known_empty`, while missing/wrong completion is `unknown`/`partial`;
- coverage/freshness remain independent;
- exact duplicate is idempotent and same-identity changed content is conflict.

Use `batch_reconciliation.rs:142-198` as the regression shape for “commit once at marker, replay returns `Replay`, stale generation is rejected.” The new keyed tests must add dependency mutation at completion, age/inactivity expiry, fairness under capacity, and unknown-epoch fencing.

#### Fake CAS behavior for contract tests

**Source:** `crates/mind-persistence/src/fake_port.rs:8-86`.

```rust
fn compare_and_set(
    &mut self,
    expected: Option<&CheckpointCursor>,
    candidate: CheckpointEnvelope,
) -> Result<CheckpointAck, PortError> {
    candidate.encode().map_err(|_| PortError::InvalidCandidate)?;
    if let Some(retry_ack) = self.preflight(expected, &candidate)? {
        return Ok(retry_ack);
    }
    let acknowledgement = CheckpointAck::from_envelope(&candidate);
    self.acknowledged = Some(candidate);
    Ok(acknowledgement)
}
```

Copy the preflight ordering: validate candidate first; return the prior acknowledgement for exact replay; reject same-sequence changed content as collision; require exact expected predecessor for successors; accept genesis only with no predecessor. Adapt identity/digest comparisons to observation section revision and terminal receipt identities.

#### Strict versioned envelope and integrity binding

**Source:** `crates/mind-persistence/src/checkpoint.rs:7-18,37-106,144-180`.

```rust
pub const SCHEMA_VERSION: &str = "1";
pub const GAME_PROTOCOL_IDENTITY: &str = "live_galaxy.persistence.v1";

#[derive(Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct CheckpointEnvelope { /* version, identity, predecessor, hash, payload */ }

pub fn decode(bytes: &[u8]) -> Result<Self, CheckpointError> {
    if bytes.len() > MAX_ENVELOPE_BYTES {
        return Err(CheckpointError::Oversized);

    envelope.validate()?;
    Ok(envelope)

```

Reuse exact-once constants, strict unknown-field decoding, pre-allocation byte bound, schema/protocol validation, and integrity binding. Define observation schema/policy/canonicalization/digest versions once; do not reuse mind checkpoint payload fields or protocol identity. Use `sha2::Sha256` for observation content/manifest identity as approved by research.

#### Recovery and crash cuts

**Source:** `crates/mind-persistence/src/recovery.rs:4-18,66-184`.

```rust
pub enum CrashPoint {
    BeforeX4Write,
    AfterX4WriteBeforeAcknowledgement,
    AfterAcknowledgementBeforeProjection,
}

pub fn recover(input: RecoveryInput) -> RecoveryOutcome {
    match input {
        RecoveryInput::Crashed { acknowledged, point } => recover_crash(acknowledged, point),
        RecoveryInput::Candidate { acknowledged, candidate } => {
            recover_candidate(acknowledged, &candidate)
        }
        // migration remains explicit and bounded
    }
}
```

Use the same explicit crash-cut fixture style, but cut around immutable revision content insertion, terminal receipt insertion, current-pointer update, SQLite commit, and post-commit response emission. Recovery must expose either the previous or new complete revision, never mixed content, a pointer without content, a receipt without content, or duplicate publication. Unconfirmed commit I/O is ambiguous: reconcile exact durable receipt and pointer before retrying.

#### SQLite adapter (no direct analog)

No existing observation-specific repository or SQLite adapter exists. Use `rusqlite = 0.40.2` with `default-features = false, features = ["bundled"]` as approved in RESEARCH.md. The new adapter should follow the port seam, use one immediate transaction for immutable revision content + terminal receipt + conditional current pointer, enforce foreign-key/unique constraints, and keep current/decision-pinned revisions reachable during bounded retention. Do not build a generic persistence framework or use multi-file rename/separate writes.

#### Persistence tests

**Sources:** `crates/mind-persistence/tests/fake_port_contract.rs:43-80`, `recovery_contract.rs:52-200`, `schema_contract.rs:7-34`, `checkpoint_tracer.rs:87-117`.

## Shared Patterns

### Strict input and fail-closed diagnostics

**Sources:** `crates/observation-ingest/src/wire.rs:34-42,104-151`; `crates/observation-ingest/src/model.rs:7-45,114-124`; `crates/observation-ingest/tests/atomic_rejection.rs:42-112`.

Check raw byte size before decode, reject unknown fields and invalid typed values, map to bounded typed reason codes, and never retain or echo raw payloads. Rejected input returns the unchanged accepted projection plus bounded evidence; no partial candidate becomes eligible.

### Deterministic ordering and injected time

**Sources:** `crates/observation-ingest/src/completion.rs:11-25`; `crates/observation-ingest/src/lib.rs:33-67`; `crates/observation-domain/src/reconciliation.rs:75-104`.

Sort canonical keys before digest/replay comparisons, use checked counters, and inject clocks (`ReceiptClock`) instead of sleeps or wall-clock calls in policy tests. Game time may affect urgency only; real-time budgets and finite work permits remain authoritative.

### Atomic state transitions

**Sources:** `crates/observation-ingest/src/batch.rs:28-106`; `crates/mind-persistence/src/fake_port.rs:56-86`; `docs/ARCHITECTURE.md:1234-1271`.

Validate into private state, then publish exactly once. A failure discards only private state; durable publication binds content, receipt, and current pointer in one transaction. Emit `received` only after volatile staging and `committed` only after durable commit. A pipe/local handoff is neither.

### Evidence language and boundaries

Local Rust/fake/SQLite tests prove generic contracts and persistence only. They do not prove Carrier B, Lua/MD lifecycle, X4 scheduling, SETA, save boundaries, or observed-in-X4 behavior. Keep all such runtime claims in Phase 05.4+.
