## Critical Issues

### CR-01 (P1/BLOCKER): A coordinated manifest forgery authenticates and executes attacker-controlled components

**Files:** `tools/x4-verification/run-candidate-package.ps1:91-116,309-321`,
`tools/x4-verification/build-candidate-extension.ps1:386-412`,
`tools/x4-verification/tests/candidate_package_adversarial.ps1:104-122`

**Issue:** The immutable snapshot closes the original validation-to-use swap,
but the snapshot and component-binding checks trust digests supplied by the
same unsigned, caller-writable build manifest as the component bytes. Owner-only
ACLs prevent access by other accounts; they do not authenticate bytes against
the repository to the same-account caller that invokes the dispatcher. The
repository dispatcher therefore accepts a coordinated rewrite of a component,
its top-level binding digest, and its `generated_files` digest/length row.

An independent black-box probe prefixed the packaged adapter with a marker
write, recomputed both manifest-controlled adapter digests and the byte count,
restored owner-only ACLs, and invoked the repository dispatcher. It returned
exit 0 with `local_process_ready=true`, published a passing evidence file, and
the marker proved that the forged adapter executed. The current adversarial
test changes either a component without its manifest or a graph digest without
recomputing its dependent declarations, so it does not exercise this attack.

**Fix:** Authenticate the entire exact build manifest before importing or
launching any snapshot component, or pin every executable/protocol digest to an
immutable trusted repository source outside the caller-controlled package.
Add a held-out coordinated-tamper test that changes a component and every
self-declared digest and proves that neither code execution nor publication
occurs.

### CR-02 (P1/BLOCKER): Identity and volume adapters still emit fixture-independent observations

**Files:** `tools/x4-verification/candidate-adapters.psm1:105-120`,
`tools/x4-verification/tests/candidate_package_runtime_contract.ps1:36-64`

**Issue:** The new adapters no longer echo `ExpectedResult`, but two of seven
still return hard-coded observations that are not computed from the accepted
fixture. The identity adapter accepts any matching native/canonical IDs yet
always claims `object=station-01` and `owner=argon`. The volume adapter accepts
any bounded sample and payload counts yet always claims 8 samples and 2048
bytes and emits `volume:8-samples/2048-bytes`.

Independent executable probes supplied valid alternate fixtures. A matching
`ship-99`/`boron` identity completed while claiming `station-01`/`argon`; a
7-sample, 1000-byte volume completed while claiming 8 samples and 2048 bytes.
The runtime suite uses one exact happy fixture and one invalid fixture for each
adapter, so both incorrect observations pass its independent-result assertion.

**Fix:** Derive `actual_result`, observations, and work units from the validated
fixture fields. If only the fixed values are contractually meaningful, reject
every other value explicitly instead. Add alternate-valid held-out fixtures and
compute their expected observations independently of the adapter.

### CR-03 (P1/BLOCKER): A signed producer claim may complete in the future

**Files:** `tools/x4-verification/producer-attestation.psm1:109-128`,
`tools/x4-verification/tests/evidence_retention_contract.ps1:514-522`

**Issue:** Producer validation enforces `completed_at >= started_at`, expiry
after completion, a 24-hour lifetime, a five-minute future-start allowance, and
current expiry. It never enforces that `completed_at` is at or before the
validation time plus the permitted clock skew. A claim can therefore assert a
completed run and evidence digest from the future and remain retainable when
correctly signed.

An independent executable call supplied `started_at=now`,
`completed_at=now+1h`, and `expires_at=now+2h`; the validator returned true.
The existing `future issuance` test sets both start and completion in the
future, so it is rejected by the future-start check and never reaches this
missing chronology constraint.

**Fix:** Require `started_at <= completed_at <= Now + permitted_clock_skew <
expires_at`. Add a separately signed future-completion negative whose start is
not in the future, so the test proves the completion bound itself.
