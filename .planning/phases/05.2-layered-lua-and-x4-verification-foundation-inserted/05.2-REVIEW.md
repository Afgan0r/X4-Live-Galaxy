## Critical Issues

### CR-01 (P1/BLOCKER): Two required generated files remain outside the exact-byte trust anchor

**Files:** `tools/x4-verification/run-candidate-package.ps1:135-145,198-230`,
`tools/x4-verification/tests/candidate_package_adversarial.ps1:175-225`

**Issue:** `Assert-TrustedGeneratedPackage` reconstructs `content.xml`,
`ui.xml`, and the generated entrypoint as exact UTF-8 bytes and compares the
runner to its repository source. In contrast, it parses
`manifest/candidate-matrix-subset.v1.json` and
`manifest/package-conformance.v1.json`, then calls `Assert-ExactJson`.
`Assert-ExactJson` reserializes both objects, so alternate source bytes that
parse to the same object are accepted. The adversarial test covers only
content, UI, entrypoint, and runner coordinated rewrites; it never mutates the
two remaining generated files.

An independent black-box probe appended valid JSON whitespace to each file,
recomputed the matching `generated_files` byte count and SHA-256, rewrote the
manifest, restored owner-only ACLs, and invoked the repository dispatcher.
Both mutations exited 0, returned local PASS, and published JSONL evidence.
The same probe covered all 13 generated paths: the other 11 exited 1 with
`COMPONENT_DIGEST_MISMATCH` and created neither evidence nor attestation. The
accepted pair therefore disproves the required complete generated-byte anchor;
a producer signer would be asked to attest after this undetected rewrite.

**Fix:** Generate the expected subset and package contract with the exact same
canonical byte writer used by the builder, then compare bytes/digests rather
than parsed-object serialization. Prefer one shared deterministic serializer
or shared generation module so the builder and dispatcher cannot drift. Add
held-out mutations for whitespace, property-order/escape representation, and
duplicate-key spellings; recompute every self-declared digest and assert nonzero
exit plus absence of both evidence and attestation.

### WR-01 (P2/WARNING): Five adapters still complete above the caller's work budget

**Files:** `tools/x4-verification/candidate-adapters.psm1:68-115`,
`tools/x4-verification/tests/candidate_package_runtime_contract.ps1:58-107`

**Issue:** The new derived-budget guards exist only in the identity and volume
branches. Cadence returns four units, lifecycle three, mod-stack four,
count/fill three, and fill-completeness three without comparing those required
units to `MaxWorkUnits`. Independent valid calls with `MaxWorkUnits=1` returned
`status=completed` and those 4/3/4/3/3 work counts. Identity and volume correctly
returned `adapter-work-budget-exceeded`, proving the fix distinguishes its two
named examples but not the shared exported-adapter contract. The worker later
rejects an over-budget response, so the repository dispatcher fails closed,
but direct callers receive a completed result that violates their bound and the
failure occurs at the wrong boundary.

**Fix:** Centralize completion construction behind a helper that rejects when
the computed `WorkUnits` exceeds `MaxWorkUnits`, or perform the same pre-check
in every branch before `New-Completion`. Parameterize the runtime contract over
all seven valid fixtures and require budget `required - 1` to return incomplete
`adapter-work-budget-exceeded` without a completed result.
