## Summary

The post-Plan-10 implementation still has three shipping blockers at its trust
boundaries. Static package conformance can be forged with inert Lua text, the
pure-Lua runner silently accepts sparse collections, and the package dispatcher
allocates attacker-declared files before validating their fixed contract. Two
additional defects leave bounded readers raceable and owner-authority tests dead.

The focused `x4-verification` suite passed. The full aggregate did not pass: it
stopped at `extensions/live_galaxy/tests/telemetry_contract.lua:32`, outside this
review's explicit file scope. Passing existing tests therefore does not provide a
green repository-wide closure gate.

## Critical Issues

### CR-01: Inert Lua text forges native-binding conformance

**Classification:** BLOCKER

**File:** `tools/x4-verification/x4-package-conformance.ps1:402-421`

**Issue:** Imports are derived from tokenized Lua, but native binding acquisition
is detected with a raw-source regular expression at line 408. A comment or long
string containing a line equal to `local C = ffi.C` is therefore treated as an
executable binding. A held-out package containing `require("ffi")` plus that line
only inside `[[...]]` returned `verdict: conformant`, `exit 0`, and named the
decoy file as `native_binding_path`. This lets inert text satisfy a production
package trust gate.

**Fix:** Derive binding acquisition from the same lexer/parser representation as
imports and reject unsupported syntax rather than scanning raw source. Add
held-out comment, quoted-string, and all Lua long-bracket forms as negative cases.

```powershell
$tokens = @(Get-LuaTokens $source)
$hasBinding = Test-ExecutableLocalFfiCBinding -Tokens $tokens
if ($hasFfi -and $hasBinding) { $bindingPaths += $logicalPath }
```

### CR-02: Sparse Lua collections bypass exact manifest validation

**Classification:** BLOCKER

**File:** `tests/x4-candidates/lua/live_galaxy_candidate_runner.lua:79-87,104-117,210-233`

**Issue:** `copy_sorted_strings`, `validate_manifest`, and `ordered_candidates`
use `#` and `ipairs` without first requiring a dense array. Lua leaves `#` undefined
for tables with holes, while `ipairs` stops at the first hole. A held-out manifest
with valid candidates at indexes 1 and 1000 was accepted and reported
`candidate_count = 1`; the second candidate was silently discarded. The same
pattern hides sparse mod and observation entries. This violates exact-schema,
completeness, and bounded-work guarantees at the runner input boundary.

**Fix:** Require metatable-free dense arrays and use the returned exact count for
all bounds and iterations. Also reject undeclared manifest and bounds fields.

```lua
local dense, count = is_array(values)
if not dense or getmetatable(values) ~= nil or count > maximum then
    return nil
end
for index = 1, count do
    local value = values[index]
    -- validate value
end
```

### CR-03: Dispatcher allocates untrusted package data before contract validation

**Classification:** BLOCKER

**File:** `tools/x4-verification/run-candidate-package.ps1:50-52,111-135,409-421`

**Issue:** The dispatcher reads the manifest with unbounded `ReadAllBytes`, then
iterates caller-declared `generated_files` and reads each entire source file before
`Assert-TrustedGeneratedPackage` checks the repository-fixed path set. The manifest
can therefore declare an arbitrary count and byte size and force unbounded memory
allocation before the supposedly exact generated-package contract is enforced.
These reads also lack post-read path identity checks. Plan 10's four-reader test
does not exercise this direct consumer.

**Fix:** Read the manifest through a metadata-first bounded helper, validate its
exact fields, generated path set, count, and declared per-file/aggregate bounds
before snapshotting, then read each source through the same helper with post-read
identity and byte-count verification. Add max-plus-one sparse-file tests against
the dispatcher itself.

```powershell
$manifestRead = Read-BoundedFile -Path $manifestPath -Maximum 65536
$manifest = ConvertFrom-Json ([Text.Encoding]::UTF8.GetString($manifestRead.Bytes))
Assert-ExactGeneratedFileContract $manifest
foreach ($file in $manifest.generated_files) {
    $read = Read-BoundedFile -Path $source -Maximum $contract.bounds.max_file_bytes
    # verify declared bytes and digest from $read.Bytes
}
```

## Warnings

### WR-01: Worker and authority bounded reads remain TOCTOU-raceable

**Classification:** WARNING

**Files:**

- `tools/x4-verification/isolation/invoke-candidate-worker.ps1:68-73,190-196`
- `tools/x4-verification/isolation/candidate-worker.ps1:41-43`
- `tools/x4-verification/local-attestation.psm1:79-90`
- `tools/x4-verification/new-owner-override.ps1:27-33`

**Issue:** Each reader checks metadata and then reopens the path with
`Get-Content -Raw` or `ReadAllBytes` without proving that the bytes came from the
same non-reparse file or still match the checked length. A concurrent replacement
can make the parent and worker parse different requests, race an oversized payload
past a pre-allocation bound, or change authority/dossier bytes after validation.
The post-read identity invariant implemented in the four Plan-10 readers was not
applied to these adjacent trust-boundary consumers.

**Fix:** Centralize one no-reparse, metadata-first bounded byte reader and require
pre/post full path, length, last-write time, link state, and actual byte-count
agreement. Parse only the returned byte array; do not reopen the path.

### WR-02: Owner-override rejection tests are unreachable

**Classification:** WARNING

**File:** `tools/x4-verification/tests/admission_contract.ps1:300-334`

**Issue:** The `owner-override` case exits at line 301. The missing-field, broad,
stale, expired, digest-mismatch, dossier-mismatch, and invalid-decision admission
tests below it can never execute. Their final PASS marker is likewise unreachable,
so future regressions can appear covered when only the cryptographic-core tests ran.

**Fix:** Remove the obsolete unsigned-override block if the authenticated evaluator
supersedes it, or rebuild those mutations as signed envelopes and execute them before
the single case exit. Add an assertion on the expected case marker so unreachable
coverage cannot recur silently.
