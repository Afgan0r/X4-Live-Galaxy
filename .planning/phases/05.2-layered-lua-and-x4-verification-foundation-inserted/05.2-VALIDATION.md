# Phase 05.2 Validation Contract

## Validation posture

Phase 05.2 is an autonomous, fail-closed preparation phase. It does not launch
X4, inspect saves, mutate game state, or admit the Phase 05.1 discovery seam.
Runtime-only claims remain pending until a later human-run Phase 05.1 candidate
produces retained evidence that passes the independent admission policy.

The phase uses TDD for every behavior-bearing slice. Each task first adds the
named failing contract, then implements the smallest production-faithful path
that makes it pass. No package-manager installation is permitted.

## Rust invariant gate

closure preserves the repository-wide Rust contract: every Rust source remains
at most 200 physical lines; production code contains no `unwrap`, `expect`,
`panic!`, or `unsafe`; formatting and strict clippy stay green; and all inputs
crossing into existing Rust consumers remain bounded, typed, and deterministic.

the gate pass.

## Evidence retention invariant

Private runtime evidence is machine-local. The retention helper must create an
owner-only directory and owner-only JSONL/locator files, then reread every file
and verify recorded SHA-256 digests before reporting retention success. On
Windows, tests assert an ACL equivalent to directory mode `0700` and file mode
`0600`; on Unix-compatible hosts they assert those exact modes. Repository
artifacts may contain logical run IDs, schema versions, verdicts, and digests,
but never private values, raw runtime rows, secrets, usernames, or corpus paths.
