## Corrected gap checks

- **Plan 06 / R2 authority:** The production verifier consumes one fixed
  repository-relative owner-root contract and matching compiled SPKI/fingerprint
  constants. It has no root enrollment, import, replacement, selection, or
  caller-provided trust parameter. Root-signed delegated certificates bind
  purpose, monotonically accepted epoch, exact scope, validity, policy digest,
  delegated SPKI, and CNG key identity for `owner-override`,
  `candidate-producer`, and `retention-locator`. A missing/unconfigured root or
  delegated key remains fail-closed. The TEST-ONLY root is confined to the
  test fixture area and every public production entry point rejects its marker,
  fingerprint, and path. This removes the previous circular bootstrap.
- **Plan 07 / R4 isolation:** The eight named behaviors are restored before
  GREEN without deleting or filtering positive cases. Candidate declarations
  are inert and select only fixed trusted adapter IDs. Potentially blocking
  work crosses a fixed shell-disabled worker protocol with bounded I/O,
  parent deadlines, `Process.Kill(true)` tree termination, identity checks,
  partial/late/duplicate rejection, and a stable unsupported-platform result.
  Lua and the in-process runner never use `ffi.C`.
- **Plan 08 / R6 package:** All seven candidate IDs have concrete adapters,
  serial deterministic scheduling, fixed .NET SHA-256/verdict services,
  atomic owner-only JSONL output, and dispatcher-to-worker wiring. Builder
  readiness is proven by executable local self-tests and recomputed component
  and package digests; status strings are insufficient. Generated entrypoints
  are inert and developer-only. Public-package, game-install, save,
  reparse/junction, direct-native, arbitrary-command/module, and TEST-ONLY
  authority paths remain rejected. Local output is explicitly
  `authenticated-local-contract`, never `observed-in-X4`.
- **Plan 09 / R5 chain:** Retention independently rereads source/generated
  bytes, validates the Plan 08 producer delegation and complete identity
  bindings, reruns canonical package conformance, verifies owner-only atomic
  placement and digest rereads, generates the sanitized ledger itself, and
  signs a locator only with a separate root-delegated retention key. Admission
  accepts only `-VerifiedLocatorPath` output from the fixed retention verifier;
  hand-authored ledger/sanitized paths remain explicit rejection cases.
  Missing production authority remains unconfigured, while a non-Windows
  path returns `RETENTION_ATTESTATION_PLATFORM_UNSUPPORTED`, nonzero, with no
  retained artifact, locator, sanitized ledger, or success marker. Local
  chain verification is `chain-verified-x4-pending`; no plan fabricates
  `observed-in-X4` or seam admission.

## Security and provenance checks

- The plans preserve the source-saturated dossier requirement, the exact
  seven registry failure classes and one negative fixture per class, and the
  prohibition on automatic exceptions.
- The fixed root plus compiled fingerprint is independent of tool enrollment;
  delegated purpose/epoch/scope certificates and delegated-SPKI-to-CNG checks
  prevent purpose confusion, epoch rollback, key substitution, root swap, and
  signature transplant.
- Retention cannot be transplanted or forged: it recomputes evidence,
  manifest, generated-file, package-conformance, producer, and locator
  identities and signs only retention-generated sanitized data.
- Held-out tests cover fresh/replaced roots, TEST-ONLY injection, caller
  anchor redirection, purpose/scope/epoch confusion, delegated-key
  substitution, payload and signature transplant, worker identity/timeout
  races, path/junction swaps, same-length JSONL changes, forged readiness,
  failed/skipped candidates, ordering, collapsed verdicts, and unexpected
  effect passes.
- No plan launches X4, reads or modifies saves, mutates game state, changes
  the Phase 05.1 production/public runtime, installs generated roots, or
  claims local evidence is observed in X4. Production authority may remain
  explicitly unconfigured.
- The plans retain provenance/source boundaries and do not add external code
  or network acquisition.
