## CR-01: Decode Lua escapes before resolving module names

**Priority:** P2. **Status:** Closed in `4dc6f0f`.
**Location:** `extensions/live_galaxy/tests/x4-package-conformance.ps1:153`.

The changed quoted-string tokenizer removes every backslash and appends the
following character literally. A require path containing backslash followed by
`n` can therefore match an existing file even though Lua 5.1 interprets that
sequence as a newline. The reviewer confirmed this with an isolated call to
`Get-Imports` and the locked Lua interpreter.

Correctly decode the supported Lua 5.1 string forms or reject unsupported forms
explicitly before resolution. Preserve escaped quotes/backslashes and add
regression cases for semantic escapes, including decimal escapes if supported.

## CR-02: Preserve exact path case on repeated imports

**Priority:** P2. **Status:** Closed in `2bbccc1`.
**Location:** `extensions/live_galaxy/tests/x4-package-conformance.ps1:30` and `:348`.

PowerShell's case-insensitive graph maps let a differently cased import return
early from `visited` before exact-case path validation. The reviewer reproduced
the bypass by preloading the correct leaf and visiting its wrong-case spelling.
This defect was retained from the legacy checker.

Use ordinal case-sensitive maps for `visited`, `visiting`, and `sources`. Add a
two-parent fixture that visits a leaf correctly, then imports its wrong-case
spelling and requires `UNRESOLVED_IMPORT`.
