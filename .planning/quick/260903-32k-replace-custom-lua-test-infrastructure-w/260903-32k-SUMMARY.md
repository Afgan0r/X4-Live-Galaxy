## Deviations and Resolved Setup Failures

1. **Owner-approved Windows TEMP adjustment:** absolute temporary paths containing checkout spaces broke LuaRocks interpreter-output redirection; relative TEMP passed detection but failed later unpacking. The owner explicitly approved a task-specific ordinary Windows TEMP directory. It is used only as process-local installation scratch; binaries and dependency trees remain in ignored project storage.
2. **Standard exact rockspec instead of LuaRocks lock:** `make --only-deps --pin` pins the VM-provided Lua and then attempts to install it as a rock. The observed error was `Rock lua 5.1-1 is already provided by VM or via rocks_provided`. LuaRocks 3.13.0 source confirms provided rocks have no installation location while locked matches require one. The orchestrator approved exact real-package constraints and clean standard replay as the simpler technical deviation preserving reproducibility. No LuaRocks source or virtual provider was changed.
3. **Standard MSVC native compilation:** initial clang-cl compilation exposed missing upstream io/conio declarations. A temporary forced-include probe succeeded, then the completed provisioner used the already installed standard MSVC compiler without those flags; clean replay passed. No library source was patched.
4. **Absolute development root:** LuaRocks changes directory during dependency builds; the relative development path stopped header discovery. The final command uses the actual absolute development root and safely handles checkout spaces with ordinary arguments.

Official implementation evidence: [LuaRocks 3.13.0 dependency matching](https://raw.githubusercontent.com/luarocks/luarocks/v3.13.0/src/luarocks/deps.lua), [LuaRocks make contract](https://raw.githubusercontent.com/luarocks/luarocks/v3.13.0/src/luarocks/cmd/make.lua), [Busted documentation](https://lunarmodules.github.io/busted/).
